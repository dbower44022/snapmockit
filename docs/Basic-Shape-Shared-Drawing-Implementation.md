# The Shape Tools' Shared Drawing Behaviour — Implementation Notes

Last Updated: 09-12-26 12:34 · Revision 1.1

Implements the open rows of the Basic Shape Annotation Tools PRD's Section 2, Shared Shape Behavior (`PRDs/SnapMock-Basic-Shape-Annotation-Tools-PRD.html`, version 1.12 at the start), and the per-tool Drawing hints that go with them, with the General UI PRD (version 2.25) and Technical Architecture PRD (version 1.37) rows they own, in the five phases and the close-out defined by `docs/Basic-Shape-Shared-Drawing-Kickoff-Prompt.md` (revision 1.0). A session pasting that prompt starts at the first phase not marked done in Section 1. `docs/General-UI-Implementation-Kickoff-Prompt.md` (revision 1.1) governs the standards; the General UI implementation notes (`docs/General-UI-Implementation.md`) hold the walk table of Section 17.2. Finishing this work leaves the Basic Shape Annotation Tools PRD's Section 2 with no open row.

Starting state, verified at commit 0313e27 on 09-12-26 (the kickoff names 385c221; f4260c4 and 0313e27 add only documents). Three probes run against the code rather than read from it, each of which Phase 1 turns into a test:

- **A drag on a locked or on a hidden layer creates the shape.** With the Rectangle tool and the active layer locked, a press, a move, and a release leave one item in the scene; the same with the layer hidden. 2.1's first mouse-press step and the Section 12 Shared Behavior row both refuse it with a status bar warning. The marker tools do make this check, through `check_requirements`; no shape tool does, and neither does the Blur tool, whose own PRD's 8.1 row claims the same rule.
- **A tool switch during a drag leaves the preview item in the scene.** With the Rectangle tool, a press and a move put the preview in the scene; activating another tool calls `cancel` and then `deactivate`, neither of which the five drag-drawn tools override, so the preview stays — in no layer's item list, behind no command, and undeletable by an undo. `is_active_operation` is False throughout, so the Space-bar pan and the momentary Alt eyedropper can also take the drag away mid-way.
- **Shift and Alt do nothing for the Rectangle and the Ellipse.** A move at 100 by 40 pixels with Shift held gives a 100 by 40 rectangle, where 2.3 asks for a square; a move with Alt held leaves the origin at the press point, where 2.3 asks for the centre. The Line and the Arrow do constrain with Shift; the Arc constrains its chord with Shift and has no Alt; the Freehand has neither, and 9.5's straight segments are unbuilt.

The rest of the starting state, read from the code: no tool draws its preview at 70 percent opacity; there is no dimension tooltip, constrain icon, centre marker, or guide line anywhere; the Arc and the Polygon put their measurements in the status bar hint instead; every shape tool selects its new item and switches to the Select tool on release, as do the Blur and Highlighter tools; snap to grid works during drawing through `_snap_pos`. The suite at the last code commit (8a017bb) ran 1450 tests with 13 skipped and one environmental deselection: 1436 passed and one failed, the pre-existing timing-sensitive Zoom tool test, which passes alone. Ruff and mypy are clean.

## 2. Decisions

### 2.1 Taken at the start of Phase 1 (09-12-26)

Presented with the consequential decision template and chosen by Doug on 09-12-26: the recommendation in every case ("use your recommendations for all decisions").

| Decision | Choice | Effect |
|---|---|---|
| 1 Where the dimension tooltip is drawn | A, a widget over the viewport | The dimension tooltip, the constrain icon, and the centre marker are one `QWidget` child of the canvas view's viewport, raised above it and positioned in widget coordinates, as the Eyedropper's preview loupe is (Eyedropper and Blur performance decision 1). Every measurement of 2.4 is in screen pixels — a 15 by 15 pixel offset from the cursor, a repositioning rule at the viewport's edges — so the arithmetic is the viewport rectangle's and not the scene's, which the zoom changes underneath. It is never a scene item, so no render of the scene can contain it. The screen-edge positioning is factored out of `ui/loupe_overlay.py` so both overlays share one function rather than two copies of the same arithmetic. The cost: a second widget in the viewport's stacking order, which the panel-collapse modes of General UI PRD 15.2 and the focus frame painted in `SnapView.paintEvent` must leave alone, and two overlay widgets that must not fight — they cannot today, since the Eyedropper draws no shape, but a later tool could. The alternative, option B, the view's foreground pass beside the grid, the guides, the crosshairs, and the layer hover outline, would have added no widget but would have computed every position in scene coordinates and drawn the text unscaled by hand. Technical Architecture PRD 3.9 gains the row either way, and Section 10 gains one module. |
| 2 How far the not-auto-selected rule reaches | A, every drawing tool | The seven shape tools, the Blur tool, and the Highlighter all stay active on release and leave the new item unselected, so one rule holds for every tool that draws. The Numbered Step, Stamp, and Emoji tools already behave this way under their own PRD's rapid-placement rule; the Text and Callout tools are excepted, because their PRD puts a new item straight into inline edit mode. The cost: the Blur PRD gains a row where it was silent, and a user who draws one blur region and wants to resize it must press `V` first — the same cost the shape tools pay. The alternative, option B, the seven shape tools only, is this document's own scope and would have left the Blur tool and the Highlighter behaving differently from every other tool that draws. |
| 3 Whether 2.4's guide lines to the rulers are built | A, built in the foreground pass | The dashed 1 pixel lines at 30 percent opacity in the accent colour extend from the preview's bounding box to the viewport edge while a drag lasts and the rulers are visible. The grid, the guides, and the crosshairs are already drawn in `SnapView.drawForeground`, and the rulers' visibility flag is already read there, so the lines cost one more painter pass during a drag and nothing at rest. Because they are drawn from the preview's bounding box they follow the modifiers for free, and because they are a foreground pass no render of the scene can contain them. The cost: four more lines per frame during a drag, and a rule about what "to the rulers" means when one axis's ruler is hidden or the shape is off screen. The alternative, option B, a departure with a row, would have left one bullet of 2.4's five unbuilt and the section open. |
| 4 Which key draws from the centre | B, Ctrl as a second route | Every drawing tool that reads Alt for "draw from center" reads Ctrl for the same thing; Alt keeps the meaning every PRD gives it (Basic Shape 2.3, General UI 12.2). On this machine Alt plus a mouse button never reaches the canvas — Cinnamon's window manager takes it as the window-move gesture (`org.cinnamon.desktop.wm.preferences mouse-button-modifier` reads `<Alt>`, verified again 09-12-26) — so the centre-draw behaviour exists for this user only through the second route. 2.3 reserves Ctrl "for future use, such as snapping to item edges" and nothing reads it during a drag today: verified 09-12-26, no shape tool reads `ControlModifier`, the canvas view reads it only on the wheel for zoom, and the Text tool reads it for its editor shortcuts. The cost: two keys for one behaviour, which the hint text must name ("Shift: square \| Alt or Ctrl: from center"), and Ctrl is then spoken for, so the edge snapping 2.3 reserves it for needs another key or a chord when it is built. This work adds the second route in the drawing tools only; the Zoom tool's Alt+click and the blur brush's Alt+paint eraser belong to other PRDs and are named in the close-out as a follow-up. The alternatives: option A, Alt alone with the gesture recorded unreachable, which leaves the behaviour non-existent on this desktop; option C, Ctrl in place of Alt, which changes a convention built and tested in the Select tool's point editing, in the blur brush's eraser, and in the Zoom tool. |

### 2.2 The kickoff's eight silences

Each decided as the kickoff recommended, on 09-12-26, with the detail the reading added.

| Silence | Decision |
|---|---|
| Where the locked and hidden layer check lives | One `BaseTool` helper the shape tools call from `mouse_press`, not seven copies, using `check_requirements` as the marker tools do, so the message reads as General UI PRD 1.3 asks and no control is disabled. The action name in the message is the tool's own display name, as the Numbered Step tool's is. |
| Whether the preview joins the scene | It is added to the scene during the drag, as it is today, rather than drawn by an overlay. 2.1 calls it "a temporary preview item, not yet added to the scene's item collection", and the scene's item collection in this code is the layer's item list, which the preview never joins. The departure is in the wording, not the behaviour. 2.4's 70 percent opacity is applied to that item and cleared when it is committed. |
| A modifier pressed mid-drag | Takes effect from that moment, without the drag restarting: the tools already recompute the geometry from the press point on every move. |
| The Ellipse's Shift-held hint | 6.7's Shift-held row reads a diameter, so a circle's tooltip and hint show `D:` where an ellipse's show `W:` and `H:`. The same rule gives the Rectangle's square no separate row, since 5.7 lists none. |
| The Freehand's Shift segments | Snap to horizontal, vertical, and 45 degrees from the last direction change point, which 9.5 defines; the Freehand keeps 9.5's four directions rather than 2.3's twelve. |
| Where the measurements come from | One function per tool computes the measurements; the tooltip shows them and the hint text is built from the same values, so the two can never disagree. The tooltip shows the measurement only; the status bar keeps the whole hint line with its modifier reminders. |
| The too-small threshold | A shape too small to keep is discarded on release by each tool's own present threshold; 2.1's "bounding box area under 4 square pixels, or line length under 2 pixels" is recorded as a departure where a tool differs, as the Freehand's already is. |
| When the guide lines are drawn | Only while a drag lasts, never for a placed item, and only on the axes whose ruler is visible. |

### 2.3 Corrections to the kickoff, found in the reading

- **The shipped Idle hints of five tools are not the PRD's.** The kickoff scopes the Drawing rows of 3.7, 4.8, 5.7, 6.7, and 9.11 and says the Rectangle's and Ellipse's idle hints "already promise the modifier". They promise Shift and not Alt, and they are not the tables' wording: the code reads `"Click and drag to draw rectangle | Shift: square"` where 5.7 reads `"Click and drag to draw a rectangle. Shift: square. Alt: from center."` The Line's, Arrow's, and Freehand's differ the same way; the Arc's and the Polygon's are verbatim. Phase 4 therefore corrects the five Idle rows as well as building the five Drawing rows, and decision 4's second route is named in both.
- **General UI PRD 6.6 already carries a forbidden-cursor row.** "Tool over locked layer item" names a locked *item*, not a locked layer, so it does not cover the press guard of 2.1. Phase 1 records that the two rules are separate rather than letting them read as one; no cursor change is built for the press guard.
- **The Blur tool switches to the Select tool from three places, not one.** `tools/blur_tool.py` calls `_switch_to_select` at three release paths (the drag-drawn region, the Whole Layer region, and the brush-painted region). Decision 2's option A reaches all three.

## 3. What Phase 1 built

Step 1, ea4f535: the decisions of Section 2.1, the silences of 2.2, and the corrections of 2.3; Basic Shape PRD 1.13, Blur PRD 1.15, General UI PRD 2.26, Technical Architecture PRD 1.38.

Step 2, 1e71cd0: the shared drawing lifecycle, in `tools/base_tool.py` and the nine tools that draw.

`BaseTool.layer_allows_drawing` is the press guard of 2.1: the active layer must be visible and unlocked, and a press that fails is refused with the never-disabled message of General UI PRD 1.3 through `check_requirements`, which names exactly which of the two requirements is missing. The seven shape tools, the Blur tool (its own PRD's 8.1 row), and the Highlighter call it from `mouse_press`; the Numbered Step tool's `_layer_allows_placing` now delegates to it and its own copy of the rule is gone.

`BaseTool._start_preview` and `_end_preview` hold the drawing preview, so `cancel` drops it and `is_active_operation` is true for as long as a drag lasts. `handle_escape` cancels a drawing operation, which is 2.3's Escape row, reached from the window through the Edit > Deselect shortcut. The five drag-drawn shape tools — Rectangle, Ellipse, Line, Arrow, Freehand — no longer keep the preview in an attribute of their own; each reads it back through a typed `_item` property, so there is one store and not two that can disagree. The Arc, Polygon, Blur, and Highlighter tools already tracked their own step or item and keep their overrides.

Silences found while building, decided as the code says:

- The attribute is `_preview_item`, not `_preview`: the Eyedropper tool already has a `_preview` method, and mypy strict refuses the clash.
- `handle_escape` and `is_active_operation` on `BaseTool` consult the preview alone, so the eleven tools that keep an operation of their own are untouched: the attribute is None for them, `is_active_operation` still reads False, and Edit > Deselect still runs on Escape. Making the base cancel every operation would have changed the Crop, Raster Selection, Lasso, Text, Callout, Pan, Zoom, Stamp, Emoji, and Numbered Step tools, none of which this work owns.
- The Blur tool's guard runs when a region is begun, not on each stroke that continues one already painted (2.3's brush): a stroke that adds to a region already in progress is not a new press in 2.1's sense. The same reading gives the Polygon tool its guard on the first press only, since the clicks that follow place vertices in a shape already begun.
- The action name in the message is the tool's own display name. That reproduces the Numbered Step tool's existing wording exactly — "Numbered Step needs an unlocked active layer." — so that tool's copy could be deleted rather than left beside the shared rule.
- `is_active_operation` was already right for the Arc, Polygon, Blur, and Highlighter tools; only the five drag-drawn tools reported False throughout a drag, which is what let the Space-bar pan, the momentary Alt eyedropper, a focus loss, and the undo guard take a drag away mid-way.
- A press refused by the guard returns True, consuming the event, so the scene's own handling does not run behind the message.

## 4. Tests

Phase 1: `tests/test_shape_drawing_lifecycle.py` (37). The press guard: each of the five drag-drawn tools refused on a locked layer and on a hidden one with its message, both requirements named together when both are unmet, the Highlighter and the Blur tool making the same check through the window, and an unlocked visible layer drawing with no message at all. The preview's life: the drag reported as an active operation from the press to the release, and `cancel`, Escape, a tool switch, and a focus loss each leaving nothing in the scene and nothing on the command stack; the Space-bar pan and the momentary Alt eyedropper standing down while a drag lasts; and the Highlighter reporting its drag as it did before. The `unmet_messages` fixture captures the never-disabled message, so no test opens a real dialog.

A targeted run over twenty-five modules at the step 2 commit passed 378 tests with one deselected and one failure, `tests/test_tools/test_zoom_tool.py::test_alt_at_the_press_alone_zooms_out`, of the same timing-sensitive family as the pre-existing one; all five Zoom tool tests pass alone in 2.6 seconds and nothing in that tool was touched. The run took 20 minutes.

## 5. Phase 1 close-out

The press guard of 2.1 and the Section 12 Shared Behavior row on locked and hidden layers are built, and 2.3's Escape row is built for every shape tool. 2.1's mouse-press list is met but for its preview wording, which is the silence of Section 2.2 and not a behaviour: the preview is a scene item and never joins the active layer's item list. 2.1's mouse-release list still has its last step open — the new item is selected and the tool switches away — which is Phase 5's.

**Next required step:** Phase 2, the modifiers (2.3, 9.5) — Shift squaring the Rectangle and circling the Ellipse from the press point; the centre-draw modifier of decision 4, Alt or Ctrl, on the Rectangle, the Ellipse, and the Arc; the two together; and Shift holding a Freehand stroke to horizontal, vertical, and 45-degree segments from the last direction change. Tests: each modifier on each tool by geometry, both together, a modifier pressed and released mid-drag taking effect from that moment, and a Freehand stroke mixing a curve and a straight segment.
