Document Overview

Purpose

This document defines the detailed functional requirements for the two text-bearing annotation tools in SnapMock: the Text Box tool and the Callout Bubble tool. Both tools share a common rich-text editing engine, so this PRD begins with a comprehensive specification of the shared text engine before covering each tool's unique behavior.

Scope

This PRD covers: the rich-text data model and rendering engine, inline text editing (cursor, selection, keyboard input), text-specific clipboard behavior, the Text Box tool's creation and editing workflow, the Callout Bubble tool's creation and editing workflow including tail and bubble geometry, data models, command definitions, serialization, and acceptance criteria.

Dependencies

  • Technical Architecture PRD: SnapGraphicsItem, VectorItem base, CommandStack, BaseTool interface.
  • General UI PRD: Tool Options Bar text controls (font, size, bold/italic/underline, alignment, color).
  • Navigation & Raster Operations PRD: Select / Move tool handles post-creation selection, move, resize. TransformHandles for bounding box resize.
  • Basic Shape Annotation Tools PRD: Shared VectorItem properties (stroke, fill, opacity, shadow) apply to the text box frame and callout bubble body.

Rich Text Engine

Both TextItem and CalloutItem contain rich text content. Rather than implementing a custom text engine from scratch, SnapMock leverages Qt's QTextDocument and QTextEdit infrastructure. This section defines how that infrastructure is configured and integrated.

Text Model Architecture

QTextDocument as Data Model:

  • Each TextItem and CalloutItem owns a QTextDocument instance that stores the text content and formatting.
  • QTextDocument provides a block-based model: a document contains blocks (paragraphs), each block contains text fragments with formatting (QTextCharFormat).
  • This model supports mixed formatting within a single text item (e.g., one word bold, another italic, different colors).
  • QTextDocument handles all text layout, line wrapping, and measurement.

Integration with QGraphicsScene:

  • Text items are NOT based on QGraphicsTextItem (which has limitations with custom rendering and transforms). Instead, they are custom SnapGraphicsItems that own a QTextDocument and render it via QPainter.
  • This gives full control over rendering (custom backgrounds, borders, shadows, callout tails) while leveraging QTextDocument for text layout and editing.
  • For inline editing, a hidden QTextEdit (or its document interface via QTextCursor) is used to handle keyboard input, cursor positioning, and text selection. The visual rendering is performed by the item itself.

Text Layout & Rendering

Text Area Calculation:

  • The text area is the interior of the text box or callout bubble, inset by padding on all four sides.
  • Padding default: 8px on all sides. Configurable per item.
  • QTextDocument.setTextWidth() is called with the text area width to enable word wrapping.
  • If auto_height is enabled (default for TextItem), the text box height grows to fit the content. QTextDocument.size().height() + top_padding + bottom_padding determines the item height.
  • If auto_height is disabled (fixed-size mode) and text exceeds the box height, the text overflows outside the box boundary but remains fully visible. Text is never clipped or hidden.

Rendering Pipeline:

  1. Draw the item shadow (if enabled).
  2. Draw the background fill (if enabled) clipped to the item's shape path.
  3. Draw the border/stroke (if enabled) along the item's shape path.
  4. If in edit mode, set the QPainter clip region to the text area (inset by padding from the shape boundary). If not in edit mode, do not clip — text that overflows the boundary renders visibly outside the box.
  5. Call QTextDocument.drawContents(painter, text_area_rect) to render the formatted text.
  6. Draw any additional decorations (callout tail, resize handles when selected).
  7. If flip_horizontal or flip_vertical is True (inherited from SnapGraphicsItem base class): apply QPainter scale(-1, 1) or scale(1, -1) respectively around the bounding box center. Flip transforms are applied after rotation in the rendering transform order: translate to position, rotate, flip, then render content.

Anti-Aliasing:

Text is always rendered with QPainter.Antialiasing and QPainter.TextAntialiasing hints enabled for crisp rendering at all zoom levels. At zoom levels above 400%, sub-pixel text rendering may be disabled to show exact pixel boundaries.

Inline Editing Mode

Entering Edit Mode:

  • Double-click a TextItem or CalloutItem with the Select tool to enter inline text editing mode.
  • Alternatively, activating the Text tool (T) and clicking on an existing TextItem enters edit mode for that item.
  • When the Text tool is active and the user clicks on empty canvas, a new TextItem is created and immediately enters edit mode.
  • On entering edit mode: the item's appearance changes to show an editing state: the border becomes a solid accent-color line (2px), the background becomes slightly lighter/different to indicate editability, and a text cursor (blinking I-beam) appears at the click position within the text.

Editing State:

  • While in edit mode, all keyboard input is directed to the item's QTextDocument via a QTextCursor.
  • The text cursor blinks at 500ms intervals (standard cursor blink rate).
  • Typing inserts characters at the cursor position.
  • Backspace deletes the character before the cursor. Delete removes the character after the cursor.
  • Enter creates a new paragraph (new QTextBlock).
  • Shift+Enter creates a soft line break (QTextCursor.insertText("\n") within the same block).
  • Tab inserts 4 spaces (not a tab character, to avoid rendering inconsistency).
  • All text modifications are recorded as TextEditCommand entries for undo/redo (see Section 6).

Exiting Edit Mode:

  • Click outside the text item (on canvas or another item).
  • Press Escape.
  • Switch to a different tool.
  • On exit: finalize any pending TextEditCommand, restore the item's normal appearance (remove the editing border), deselect the text cursor. If the text content is completely empty (no characters), remove the item entirely (treat as an abandoned creation) and push a RemoveItemCommand.

Text Selection & Cursor

Cursor Positioning:

  • Clicking within the text area positions the text cursor at the nearest character boundary.
  • The cursor position is determined by QTextDocument.documentLayout().hitTest(point, Qt.FuzzyHit).
  • The cursor is rendered as a 2px wide vertical line, 1px taller than the line height, colored with the accent color.
  • Home key: move cursor to the start of the current line. End key: move to the end of the current line.
  • Ctrl+Home: move to the start of the document. Ctrl+End: move to the end.

Text Selection:

  • Click and drag within the text area selects text between the press and release positions.
  • Shift+click extends the selection from the current cursor position to the click position.
  • Shift+arrow keys extend the selection character by character (or word by word with Ctrl+Shift+arrow).
  • Ctrl+A selects all text within the item (not all items on the canvas; that shortcut is overridden while in edit mode).
  • Double-click selects the word under the cursor.
  • Triple-click selects the entire paragraph (QTextBlock) under the cursor.
  • Selected text is highlighted with the system selection color (or a custom accent color at 30% opacity).
  • While text is selected, typing replaces the selection. Backspace or Delete removes the selection.

Clipboard Integration

Copy from Text Item:

  • When text is selected within an editing text item and Ctrl+C is pressed: place the selected text on the system clipboard in both plain text and HTML format (preserving formatting).
  • Also store the selected text on the internal clipboard as a "text/x-snapmock-richtext" MIME type containing the QTextDocumentFragment serialized as HTML.

Paste into Text Item:

  • Ctrl+V (plain paste): strip all formatting from the clipboard content and insert as plain text using the current cursor format (font, size, color at the cursor position).
  • Ctrl+Shift+V (rich paste): attempt to preserve formatting. If the clipboard contains HTML, parse it and convert to QTextCharFormat/QTextBlockFormat. If it contains the internal "text/x-snapmock-richtext" format, use it directly.
  • If pasting from an external source (e.g., a web browser), sanitize the HTML: strip scripts, iframes, images (images are not supported inline within text items), and limit formatting to the supported character and paragraph formats listed in Section 2.2.
  • Pasting plain text respects line breaks: each \n creates a new QTextBlock.

Copy/Paste Priority (During Text Editing):

While in text editing mode, Ctrl+C and Ctrl+V operate on the text content (not on scene items). This overrides the global clipboard behavior defined in the Navigation & Raster Operations PRD. When the user exits text editing mode, Ctrl+C/V return to their global behavior (copying/pasting scene items).

Find/Replace Within Text

  • When in text editing mode, Ctrl+F opens a small inline find bar at the top of the text item (not a modal dialog).
  • The find bar contains: a search text field, Previous/Next buttons, a Case Sensitive toggle, a Close button.
  • Matches are highlighted in yellow (background) within the text item.
  • Ctrl+H extends the find bar to include a Replace field and Replace/Replace All buttons.
  • Find/Replace operates only within the current text item, not across all items on the canvas.
  • Replace All pushes a single TextEditCommand for the entire batch replacement.
  • Escape or the Close button dismisses the find bar.

The Text Box tool creates rectangular text containers with optional background fill, border, and shadow. Text boxes are the primary way to add labels, annotations, notes, and descriptions to screenshots and mockups.

Creation Workflow

3.2.1 Click-to-Create (Quick Mode):

  1. With the Text tool active, click once on empty canvas.
  2. A new TextItem is created at the click position with a minimum width of 200px. Both auto_width and auto_height are enabled.
  3. The item immediately enters inline editing mode with the cursor placed at position 0.
  4. The user begins typing. The box auto-sizes in both width and height to fit the text content. The width never shrinks below the 200px minimum. See Section 3.4.1.
  5. If the user clicks and immediately presses Escape (without typing), the empty item is removed.

3.2.2 Drag-to-Create (Sized Mode):

  1. With the Text tool active, click and drag on empty canvas.
  2. A preview rectangle is drawn showing the text box dimensions (same visual as Rectangle tool preview).
  3. Shift constrains to a square. Alt draws from center.
  4. On release, a TextItem is created. The drawn dimensions set the minimum width and minimum height for the text box. Both auto_width and auto_height are enabled. The box auto-sizes to fit text content but never shrinks below the drawn dimensions. See Section 3.4.1.
  5. The item immediately enters inline editing mode.
  6. If the drawn area is less than 20x20 pixels, treat as a click-to-create instead.

3.2.3 Click on Existing TextItem:

  • If the Text tool is active and the user clicks on an existing TextItem, enter inline editing mode for that item at the click position.
  • This allows quick editing without switching to the Select tool first.

Auto-Size and Resize Behavior

3.4.1 During Text Entry (Edit Mode):

  • While the text box is in edit mode, both width and height auto-size to fit the text content at all times. All entered text is always fully visible.
  • Word wrapping is disabled during edit mode. Each line extends horizontally as far as the user types. Lines only break on Enter (new paragraph) or pasted newlines.
  • After each keystroke or paste operation, the box dimensions are recalculated: width = max(all line widths) + padding_left + padding_right; height = QTextDocument.size().height() + padding_top + padding_bottom.
  • The box dimensions never shrink below the minimum size. For click-to-create, the minimum width is 200px. For drag-to-create, the minimum width and height are the dimensions drawn by the user. The minimum height for click-to-create is 1 line of text + padding.
  • Alignment settings from the Tool Options Bar are applied in real time during text entry. The user always sees text positioned (Left, Center, Right, Justify; Top, Middle, Bottom) as it will appear in the final result, consistent with WYSIWYG behavior.
  • If a text_scale_factor is applied (see Section 3.4.3), auto-sizing and editing operate at the scaled visual size. The cursor, selection highlights, and newly typed text all render at the scaled size to maintain WYSIWYG fidelity.
  • Auto-size growth anchors at the top-left corner: the top-left position stays fixed and the right and bottom edges expand outward.

3.4.2 Post-Entry Normal Resize (No Modifier Key):

  • When the user exits edit mode and selects the text box with the Select tool, dragging any TransformHandle resizes the box freely in both width and height.
  • Text reflows (word wraps) to fit the new width. Line breaks change dynamically as the width changes.
  • If the text box is resized smaller than the text content requires, the text overflows outside the text box boundary but remains fully visible. Under no circumstance is entered text hidden, clipped, or truncated.
  • If the text box is larger than the text content, the text is positioned within the box according to the alignment settings: horizontal (Left, Center, Right, Justify) and vertical (Top, Middle, Bottom).
  • Minimum resize dimensions: 20px width, 16px height.

3.4.3 Post-Entry Shift+Resize (Scale Mode):

  • When the user holds Shift while dragging a TransformHandle, the text scales proportionally to fit the new box dimensions. The text does not reflow — all existing line breaks are preserved.
  • Scaling is implemented via a text_scale_factor property (float, default 1.0) applied at render time. The underlying QTextDocument font sizes are not modified. The QPainter is scaled by text_scale_factor before drawing the text content.
  • The scale factor preserves relative size ratios between differently-sized text. For example, 14pt and 24pt text at scale 0.5 render at 7pt and 12pt visual sizes respectively.
  • The text_scale_factor allows fractional rendering sizes that cannot be achieved with integer or half-point font sizes alone.
  • The scale factor applies at all times, including during subsequent edit mode sessions, ensuring WYSIWYG behavior.
  • The text_scale_factor is serialized as a property on the TextItem and persists across save/load.

3.4.4 Scale Factor Reset on Explicit Font Size Selection:

  • If the user enters edit mode on a text box that has a text_scale_factor other than 1.0, selects any portion of text, and explicitly chooses a font size from the Tool Options Bar, the following sequence occurs as a single undoable command:
  • Bake the current scale factor into all text in the box: every character’s font size is multiplied by the current text_scale_factor (e.g., 14pt at scale 0.5 becomes 7pt).
  • Reset text_scale_factor to 1.0.
  • Apply the user’s chosen font size to the selected portion of text.
  • After this operation, all text displays at the same visual sizes as before the reset, except the selected portion which displays at the explicitly chosen size. No visual discontinuity occurs for the unselected text.

Tool Options Bar

The Text tool's Tool Options Bar shows the following controls (left to right):

  1. Font Family: QFontComboBox with font preview rendering. Shows the current font for the selection or cursor position.
  2. Font Size: editable QComboBox with common sizes (8, 9, 10, 11, 12, 14, 18, 24, 30, 36, 48, 60, 72) and free text entry. Shows the current size; "Mixed" if the selection spans multiple sizes.
  3. Bold (B): toggle button. Shows pressed state when the selection/cursor is bold.
  4. Italic (I): toggle button.
  5. Underline (U): toggle button.
  6. Strikethrough (S with line): toggle button.
  7. Text Color: color swatch button. Click for color picker popover.
  8. Text Highlight: color swatch button with a small "marker" icon. Click for color picker with a "No Highlight" option.
  9. Text Alignment: toggle button group (Left, Center, Right, Justify). Shows the alignment of the current paragraph.
  10. Background Color: color swatch button for the text box background fill (not per-character).
  11. Vertical Alignment: dropdown (Top, Middle, Bottom).
  12. Border Color: color swatch button for the text box border.
  13. Border Width: spinbox (0 to 20px, step 0.5). 0 = no border.
  14. Border Style: dropdown (Solid, Dashed, Dotted, DashDot, DashDotDot).

When no text item is selected and the tool is active, changing Tool Options Bar values sets the defaults for the next created text box. When a text item is being edited, changes apply to the current selection or cursor position immediately.

Post-Creation Editing

Inline Text Editing:

As described in Section 2.4. Double-click with Select tool or click with Text tool to enter edit mode. All rich text editing capabilities apply.

Box Resize (Select Tool):

  • Resize behavior follows the rules defined in Section 3.4. Without modifier keys: the box resizes freely, text reflows to the new width, and text that exceeds the box boundary overflows visibly and is never hidden. See Section 3.4.2.
  • With Shift held: the text scales proportionally to fit the new box dimensions without reflowing. The text_scale_factor property is updated. See Section 3.4.3.
  • Dragging corner TransformHandles resizes both width and height simultaneously.
  • Dragging edge midpoint handles resizes only the corresponding dimension (left/right midpoints change width only; top/bottom midpoints change height only).
  • Minimum resize dimensions: 20px width, 16px height.

Property Panel Behavior:

  • Tool selected, no item created: When the Text tool is selected but no text box has been created or selected, the Property Panel displays the Text section (see General UI PRD Section 8.4) populated with the tool’s default properties. This allows the user to review and configure settings such as font family, font size, text color, alignment, and background fill before creating a text box. The Font Size control receives focus so the user can change it immediately without additional clicks.
  • Text edit mode (actively typing): While in inline text editing mode, the Property Panel continues to display the Text section. The displayed values depend on the current cursor and selection state as described in the following items.
  • Cursor positioned, no selection: The Property Panel reflects the character formatting at the cursor’s insertion point (the format that will be applied to newly typed text). All controls show definite values. Changes made via the Property Panel apply to subsequently typed text at that position.
  • Partial selection, uniform formatting: When the user selects a range of text where all characters share the same value for a given property, the Property Panel displays that value normally. For example, if the entire selection is Bold 12pt Arial, the Bold button appears pressed, Font Size shows 12, and Font Family shows Arial. Changes made via the Property Panel or keyboard shortcuts apply to the entire selection.
  • Partial selection, mixed formatting: When the selected text contains different values for a given property, the Property Panel shows an indeterminate (mixed) state for that property. Toggle properties (Bold, Italic, Underline, Strikethrough): the button renders in a mixed visual state (neither fully pressed nor unpressed). Value properties (Font Family, Font Size, Text Color): the control displays blank/empty. Alignment (Left, Center, Right, Justify): since alignment is paragraph-level, it reflects the paragraph(s) containing the selection; if multiple paragraphs with different alignments are selected, the alignment buttons show a mixed state. When the user sets a value on a mixed-state property, the new value is applied uniformly to the entire selection, and the control updates to show the definite value.
  • Real-time synchronization: When the user applies formatting via keyboard shortcuts (Ctrl+B, Ctrl+I, Ctrl+U, etc.) while text is selected, the Property Panel must update immediately to reflect the new formatting state. The panel does not wait for the user to deselect and reselect; the change is reflected in real time as the shortcut is executed. This also applies to formatting applied via the Tool Options Bar.
  • Text box selected, not editing: When a TextItem is selected with the Select tool but not in edit mode, the Property Panel shows the full TextItem properties (Transform, Appearance, Shadow, and Text sections). All properties from Section 3.3 are editable. Changes are applied immediately and recorded as ModifyPropertyCommand entries.

Rendering

  1. Construct the box shape path: a QRectF with optional border_radius.
  2. If shadow_enabled: draw the shadow (offset, blurred copy of the shape in shadow_color).
  3. If background_enabled: fill the shape path with background_color.
  4. If border_width > 0: stroke the shape path with border_color, border_width, and border_style.
  5. If in edit mode, set the QPainter clip to the text area (shape inset by padding). If not in edit mode, do not clip — text that overflows the boundary renders visibly outside the box.
  6. If vertical_align is Middle or Bottom: calculate the vertical offset to center or bottom-align the text block within the text area.
  7. If text_scale_factor ≠ 1.0: apply QPainter.scale(text_scale_factor) before drawing text content. Adjust the text area rect accordingly to account for the scale transform.
  8. Call QTextDocument.drawContents(painter, text_area_rect) with the appropriate vertical offset.

Hit Testing

  • If background_enabled is True or border_width > 0: the shape() returns the full rectangle path (click anywhere inside to select).
  • If both background and border are invisible (transparent background, 0 border): the shape() returns a path encompassing only the text content bounding box (so the user clicks on the text itself to select). This prevents invisible text boxes from intercepting clicks on items behind them. The text content bounding box must incorporate the vertical alignment offset calculated in Section 3.7 step 6. For example, if vertical_align is Bottom, the hit-test region is shifted downward to match where the text is actually rendered. Without this offset, the clickable area would remain at the top of the box while the visible text sits at the bottom, making the text unclickable.

The Callout Bubble tool creates speech-bubble-style annotations with a text body (the bubble) and a tail (pointer) that extends from the bubble to a target point. Callouts are used to annotate specific UI elements in screenshots with explanatory text.

Creation Workflow

Two-Step Creation:

  1. Mouse press: defines the tail tip position (the point being annotated, e.g., a button on the screenshot).
  2. Mouse drag: moves the cursor away from the tail tip to define the bubble position and size. The bubble body expands from the point opposite the tail tip. The tail stretches from the bubble to the original press position.
  3. Mouse release: finalizes the callout. The bubble is created with default dimensions (minimum 100x60px) at the release position. The tail connects from the nearest bubble edge to the tail tip (press position).
  4. Immediately enters inline text editing mode so the user can type the annotation.
  5. Shift during drag: constrains the tail angle to 15-degree increments.
  6. If the drag distance is less than 20px: create a default-sized callout (200x80px bubble) with the tail tip at the press point and the bubble positioned 80px above and to the right.
  7. Escape during drag: cancel creation.

Alternative Quick Creation:

  • Single click (no drag) on canvas: creates a default callout at the click position. The bubble is 200x80px, positioned 80px above-right of the click point. The tail tip is at the click point.
  • Immediately enters text editing mode.

Bubble Shapes

The callout bubble body can take one of several shapes:

ShapeIDDescription
Rounded Rectanglerounded_rectA rectangle with configurable corner radius. The default and most common shape. The tail attaches to the nearest edge.

Tail Geometry

4.5.1 Tail Attachment Calculation:

  • When tail_base_edge is "Auto" (default), the edge is selected based on the angle from the bubble center to the tail_tip: if the tail_tip is mostly below the bubble, the bottom edge is selected; if mostly to the right, the right edge; etc.
  • The tail_base_position along the chosen edge is auto-calculated to create the most natural look: the base is positioned where a line from the bubble center to tail_tip intersects the edge.
  • The user can override both tail_base_edge and tail_base_position in the Property Panel or by dragging the tail base handle in point-editing mode.

4.5.2 Straight Tail:

  • Two straight lines from the tail base (a segment of tail_width centered at tail_base_position on the bubble edge) converging to tail_tip.
  • The tail is filled with background_color and stroked with border_color/border_width, matching the bubble.
  • The tail integrates seamlessly with the bubble border: the bubble border is interrupted where the tail meets it, and the tail border continues smoothly from the bubble border.

4.5.3 Curved Tail:

  • Two Bezier curves from the tail base to tail_tip, creating a smooth tapered shape.
  • The control points for the curves are automatically calculated to create a natural S-curve or C-curve.
  • The curvature direction is based on the angle of the tail relative to the bubble edge.
  • The user can adjust the curvature in point-editing mode by dragging a control point on the tail.

4.5.4 Elbow Tail:

  • Two line segments meeting at a right angle, creating an L-shaped tail.
  • The first segment extends perpendicular to the bubble edge. The second segment turns 90 degrees toward tail_tip.
  • The tail maintains its tapered width (wider at the base, narrowing to tail_tip).
  • The bend point is auto-calculated but can be adjusted by dragging in point-editing mode.

4.5.5 Cloud Tail (for Cloud bubble shape):

  • Instead of a solid tail, the cloud bubble uses a series of 3-5 circles decreasing in size from the bubble edge to the tail_tip.
  • The circles are filled with background_color and stroked with border_color.
  • The circles are spaced evenly along the line from bubble edge to tail_tip.
  • Circle sizes: largest circle is tail_width/2, each subsequent circle is 60% of the previous.

Post-Creation Editing

Inline Text Editing:

Same as TextItem (Section 2.4). Double-click the bubble body to enter edit mode. The full rich text engine is available.

Select Tool Interactions:

  • Single click selects the entire callout (bubble + tail).
  • TransformHandles appear around the bounding box of the entire callout (bubble + tail tip).
  • Dragging the callout moves both the bubble and the tail tip together (maintains relative positions).
  • Resizing via corner handles resizes the bubble. The tail tip position remains fixed (the tail stretches/shrinks to maintain its target).
  • Resizing via edge midpoint handles resizes the bubble on that axis.

Point Editing Mode:

Double-clicking the tail (not the bubble text) enters point-editing mode for the tail. The following handles are available:

  • Tail Tip handle (red circle, 10x10): drag to reposition where the callout points to. This is the most commonly adjusted handle.
  • Tail Base handle (blue circle, 8x8): drag along the bubble edge to adjust where the tail attaches. Constrained to the bubble perimeter.
  • Tail Curvature handle (green circle, 8x8, visible only for Curved tails): drag to adjust the curve. Dashed guide lines connect to the base and tip.
  • Tail Bend handle (green circle, 8x8, visible only for Elbow tails): drag to adjust where the right-angle bend occurs.
  • Escape exits point-editing mode.

Distinct Double-Click Targets:

  • Double-click on the bubble body text area: enters text editing mode.
  • Double-click on the tail or bubble border: enters point-editing mode for the tail.
  • The cursor changes to indicate which mode will be entered: I-beam over text area, crosshair over tail/border.

Rendering

The rendering order for a callout is:

  1. Shadow (if enabled): rendered for the combined bubble + tail shape.
  2. Tail fill: the tail shape is filled with background_color.
  3. Bubble fill: the bubble shape is filled with background_color.
  4. Tail border: the outer edges of the tail are stroked (not the edges where the tail meets the bubble).
  5. Bubble border: the bubble outline is stroked, excluding the section where the tail attaches.
  6. Text: QTextDocument rendered inside the bubble text area (bubble_rect inset by padding).
  7. If text exceeds the bubble text area, the text overflows outside the bubble boundary but remains fully visible. Text is never clipped or hidden.

Seamless Tail Integration:

The critical rendering challenge is making the tail and bubble appear as a single unified shape. This is achieved by constructing a single QPainterPath that combines the bubble outline and tail outline into one continuous path, with the shared edges (where tail meets bubble) omitted. This combined path is used for both filling and stroking, ensuring no visible seam or double-stroke at the junction.

Hit Testing

  • The shape() returns the combined path of the bubble body and the tail. Clicking anywhere on the bubble or the tail selects the callout.
  • The tail hit area includes a 4px padding on each side to make thin tails easier to click.
  • For Cloud bubble tails (circles), each circle in the tail chain is included in the hit test path.

  • Clipboard operations (paste, cut).
  • Selection replacements (typing while text is selected).
  • Find/Replace operations.
  • A pause of more than 1000ms between keystrokes.

Serialization

Rich Text Serialization

The text content of both TextItem and CalloutItem is serialized as HTML using QTextDocument.toHtml(). This produces a self-contained HTML string with inline CSS styles for all formatting.

Example Serialized HTML:

<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.0//EN">
<html><head><meta http-equiv="content-type" content="text/html; charset=utf-8"/></head>
<body style="font-family:'Arial'; font-size:14pt; color:#000000;">
<p>This is <span style="font-weight:700;">bold</span> and
<span style="font-style:italic; color:#ff0000;">red italic</span> text.</p>
</body></html>

Deserialization:

  • On project load, QTextDocument.setHtml(html_string) restores the full rich text content with all formatting.
  • If the HTML references fonts not installed on the current system, Qt will use the default fallback font. The font name is preserved in the HTML so it will render correctly on systems where the font is available.
  • Invalid or corrupt HTML is handled gracefully: QTextDocument.setHtml() will display whatever it can parse, and the rest is silently dropped.

Font Portability

  • Fonts are referenced by family name in the HTML. SnapMock does not embed font files in the .smk project.
  • If a project is opened on a system missing a referenced font, the text renders with the system fallback font (typically a sans-serif). The original font name is preserved in the data so re-opening on the original system restores the correct font.
  • A future enhancement could embed font subsets in the .smk project for full portability. The .smk ZIP format can accommodate font files in a fonts/ directory.

  6. Text selection works correctly: click-drag, Shift+click, Shift+arrow, double-click (word), triple-click (paragraph), Ctrl+A.

  8. Copy/paste preserves rich text formatting when copying between SnapMock text items. Paste from external sources correctly strips unsupported formatting.
  9. Find/Replace works correctly within a text item with correct highlighting of matches.
  10. Text renders crisply at all zoom levels from 10% to 3200%.

Text Box Tool
