Document Overview

Purpose

This document defines the detailed functional requirements for three marker-style annotation tools in SnapMock: the Numbered Step tool (for creating sequential step indicators on screenshots), the Stamp / Sticker tool (for placing pre-designed annotation graphics), and the Emoji tool (for placing scalable emoji characters as annotation elements). These tools share a common click-to-place workflow and are grouped together because they all produce small, discrete annotation markers rather than drawn shapes or text blocks.

Scope

This PRD covers: the click-to-place interaction model, auto-numbering logic, stamp library architecture and built-in stamps, emoji picker integration, all tool-specific properties, rendering behavior, data models, serialization, and acceptance criteria. Post-creation selection, move, resize, and rotate are handled by the Select / Move tool (Navigation & Raster Operations PRD).

Dependencies

  • Technical Architecture PRD: SnapGraphicsItem, VectorItem base, CommandStack, BaseTool interface, Plugin Architecture (for stamp packs).
  • General UI PRD: Tool Options Bar layout, Left Tool Palette integration.
  • Navigation & Raster Operations PRD: Select / Move tool handles post-creation interaction.

Numbered Step Tool

Tool Overview

The Numbered Step tool creates circular (or other shaped) badges containing sequential numbers. This is the primary tool for creating step-by-step visual instructions on screenshots, such as "Step 1: Click here, Step 2: Enter your name, Step 3: Press Submit." Each click places the next number in the sequence.

Creation Workflow

Click-to-Place:

  1. With the Numbered Step tool active, click on the canvas to place a step badge.
  2. The badge is created at the click position (centered on the click point) with the next number in the auto-numbering sequence.
  3. The badge appears immediately at its default size. No dragging is required.
  4. The tool remains active after placement. The next click places the next sequential number.
  5. This allows rapid placement: click, click, click to place steps 1, 2, 3 in quick succession.

Click-and-Drag to Size:

  • Optionally, the user can click and drag to control the badge size. The badge diameter equals the drag distance (diameter = 2 * distance from center to cursor).
  • Shift constrains to a perfect circle (relevant for non-circular badge shapes).
  • On release, the badge is created with the drawn size.
  • If the drag distance is less than 10px, use the default size instead (treat as a click).

Placement Feedback:

  • On click, a brief scale-up animation (badge appears at 120% size and scales down to 100% over 150ms) provides satisfying placement feedback.
  • A subtle drop shadow pulse accompanies the animation.
  • The status bar briefly shows "Placed Step N" then returns to the standard tool hint.

Auto-Numbering Engine

Sequence Tracking:

  • The Numbered Step tool maintains a per-session sequence counter. The counter starts at the value configured in the Tool Options Bar (default: 1) and increments by 1 for each placed step.
  • The counter is global to the project, not per-layer. Steps placed on different layers continue the same sequence.
  • The counter resets when: the user manually sets a new starting number in the Tool Options Bar, or a new project is created.
  • Switching away from the Numbered Step tool and back does NOT reset the counter. The sequence continues from where it left off.

Manual Override:

  • The "Starting Number" field in the Tool Options Bar sets the number for the NEXT placed step. After placement, the counter continues incrementing from that value.
  • Example: counter is at 5, user sets Starting Number to 10, places a step (gets 10), next step is 11, etc.
  • Individual step numbers can also be edited post-creation by selecting the step and changing the number_value property in the Property Panel or by double-clicking the step to enter inline edit mode.

Renumbering Command:

  • A "Renumber All Steps" action is available via right-click context menu when a NumberedStepItem is selected.
  • This command finds all NumberedStepItems on the canvas (across all layers), sorts them by their Y position (top-to-bottom), then X position (left-to-right) as a tiebreaker, and reassigns sequential numbers starting from the configured starting number.
  • The renumber operation is a single undoable MacroCommand that contains a ModifyPropertyCommand for each step.
  • This is useful after rearranging steps or deleting intermediate steps (e.g., removing step 3 from a sequence of 1-5 and renumbering to 1-4).

Custom Text Mode:

  • Instead of a number, the step badge can display a custom short text string (1-3 characters recommended). This is set by switching the display_mode property from "number" to "text" and entering custom text.
  • Custom text examples: letter sequences (A, B, C), Roman numerals (I, II, III), check marks, or short labels.
  • When display_mode is "text", the auto-numbering counter does not advance for that step.

Label Line Feature

Numbered steps can optionally include a short text label that appears adjacent to the badge. This is useful for adding brief descriptions directly alongside the step number (e.g., step badge "1" with label "Click Login").

  • The label is part of the NumberedStepItem (not a separate item). It moves, scales, and is selected as a unit with the badge.
  • The label text is rendered in a small font next to the badge at the configured label_position.
  • If label_background_enabled is True, the label text is rendered inside a small pill-shaped background (rounded rectangle with corner_radius = label_font_size * 0.5).
  • A thin connecting line (1px, badge_color, 50% opacity) is drawn from the badge edge to the label.
  • The label can be edited inline by double-clicking the badge (enters a combined edit mode where Tab switches focus between the number/text and the label).
  • Labels are optional. When label_text is empty, no label or connecting line is rendered.

Post-Creation Editing

Select Tool:

  • Click to select. TransformHandles appear. Drag to move.
  • Resize via TransformHandles scales the badge uniformly (maintains aspect ratio by default; Shift releases the constraint).
  • Rotate via the rotate handle rotates the badge (useful for diamond and star shapes; less useful for circles).

Inline Edit (Double-Click):

  • Double-clicking a NumberedStepItem enters inline edit mode.
  • The number/text becomes an editable field. The user can type a new value directly.
  • For number mode: typing a new number overrides auto-numbering for this step. The auto-counter is not affected.
  • For text mode: the user can type up to 3 characters (more characters are allowed but may overflow the badge visually).
  • Tab key switches focus to the label text field (if label_text is configured or if the user wants to add a label).
  • Enter or Escape exits inline edit mode.

Context Menu:

  • Right-click on a selected NumberedStepItem shows the standard item context menu plus: "Renumber All Steps", "Set as Starting Number" (sets the Starting Number field in the Tool Options Bar to this step's number), "Convert to Text Mode / Convert to Number Mode" toggle.

Rendering

  1. Draw shadow (if enabled): offset, blurred copy of the badge shape in shadow_color.
  2. Draw badge fill: fill the badge shape path with badge_color.
  3. Draw badge border: stroke the badge shape with border_color, border_width, and border_style.
  4. Draw number/text: render the display string (number, letter, Roman numeral, or custom text) centered in the badge using QPainter.drawText() with the configured font, size, weight, and text_color.
  5. Auto font sizing: if font_size is 0 (auto), calculate the largest font size that fits within the badge interior (approximately badge_size * 0.55 for single digits, smaller for multi-digit/character). Use QFontMetrics.boundingRect() to measure.
  6. For the Pin shape: render the circular head with number, then the pointed tail below. The item's position anchor is at the pin point (bottom of the tail), not the center of the circle.
  7. Draw label (if configured): render the connecting line from badge edge to label position, then the label background pill (if enabled), then the label text.

Hit Testing

  • The shape() returns the badge shape path (circle, square, etc.) plus the label bounding box (if label exists).
  • For the Pin shape, the shape includes both the circular head and the triangular tail.
  • A minimum hit area of 24x24 pixels is enforced even for small badges, ensuring they remain clickable.

The Stamp / Sticker tool places pre-designed graphic elements onto the canvas. Stamps are commonly used for status indicators (approved, rejected, draft), directional markers (arrows, pointers), UI annotation symbols (cursor, click indicators, attention markers), and decorative elements. Stamps are SVG-based for resolution-independent scaling.

Stamp Library Architecture

Storage Structure:

  • Stamps are stored in the application's resources directory: resources/stamps/
  • Each stamp category is a subdirectory: resources/stamps/status/, resources/stamps/arrows/, etc.
  • Each stamp is an SVG file with optional metadata in a companion JSON file.
  • Stamp SVG files should be designed at a nominal 64x64 viewport with clean paths suitable for scaling from 16px to 512px.

Stamp Index:

  • A stamp_index.json file in resources/stamps/ catalogs all available stamps with metadata: id, name, category, filename, tags (for search), default_size, colorizable (whether the stamp supports recoloring).
  • The index is loaded at application startup and cached.
  • Custom stamps (user-added) are stored in a user data directory and merged into the index.

Colorizable Stamps:

  • Some stamps are designed to support recoloring. Their SVG uses a specific fill color placeholder (#FF0000 for primary color, #0000FF for secondary color).
  • When the user changes the stamp_color property, the placeholder colors in the SVG are replaced at render time.
  • Non-colorizable stamps (photographic or multi-color designs) render as-is regardless of the stamp_color setting.
  • The colorizable flag is set per stamp in the index metadata.

Custom Stamps

Adding Custom Stamps:

  • Users can add custom stamps via: File > Import... and selecting SVG files, or dragging SVG files onto the stamp library panel's "Custom" tab, or the Preferences > Stamps section where a "Custom Stamps Directory" can be configured.
  • Custom stamps are copied to the user's application data directory (e.g., ~/.config/snapmock/stamps/custom/).
  • Users can assign a name, category, tags, and colorizable flag to custom stamps via a simple metadata dialog.
  • Custom stamps appear in the "Custom" tab of the stamp library and are searchable by their assigned tags.

Stamp Embedding:

  • When a project is saved, stamps that are referenced by items in the project are embedded in the .smk file to ensure portability.
  • Built-in stamps are referenced by stamp_id (they ship with every SnapMock installation).
  • Custom stamps are embedded as inline SVG data in the project file. The stamp_source is set to "embedded" and svg_data contains the complete SVG.
  • On project load, if a stamp_id references a builtin stamp that exists in the current installation, the local version is used (allowing updates). If the stamp is not found locally, the embedded SVG data is used as a fallback.

Rendering

  1. Load or retrieve the cached SVG data for the stamp.
  2. If colorizable: perform color substitution on the SVG (replace #FF0000 with stamp_color, #0000FF with stamp_secondary_color).
  3. Parse the SVG using QSvgRenderer.
  4. Calculate the render rect: center the stamp at the item position, scaled to stamp_size while maintaining aspect ratio.
  5. Apply flip transforms if flip_horizontal or flip_vertical is True.
  6. Draw shadow if enabled.
  7. Render the SVG using QSvgRenderer.render(painter, target_rect).
  8. SVG rendering is resolution-independent: stamps render crisply at all zoom levels.

Hit Testing

  • The shape() returns a rectangle matching the stamp's bounding box.
  • For more precise hit testing on stamps with irregular shapes (e.g., a star), the SVG path data could be used, but the rectangular bounding box is sufficient for v1.0.
  • Minimum hit area: 24x24 pixels.

Serialization

NumberedStepItem Serialization Notes

  • The number_value is stored explicitly. The auto-numbering counter state is NOT saved in the project file (it is a tool-session concept, not a project concept).
  • On project load, the Numbered Step tool's counter is initialized to max(number_value across all NumberedStepItems) + 1 to avoid conflicts.
  • All properties including label text and styling are fully serialized.

StampItem Serialization Notes

  • Built-in stamps are referenced by stamp_id only. The SVG data is NOT stored in the project file for built-in stamps (to keep projects small).
  • Custom and embedded stamps store the full svg_data in the project file for portability.
  • When saving, any custom stamp referenced by a StampItem is embedded: its stamp_source is changed from "custom" to "embedded" and svg_data is populated.
  • On load, if stamp_source is "builtin" and the stamp_id is found in the local library, the local SVG is used. If not found, and svg_data is present (shouldn't be for builtins, but as a safety net), use the embedded data. If neither is available, render a placeholder "missing stamp" icon.
  • Color substitution values (stamp_color, stamp_secondary_color) are stored as standard hex color strings.

EmojiItem Serialization Notes

  • The emoji_char is stored as a Unicode string. Multi-code-point sequences (ZWJ sequences, skin tone modifiers) are stored as the complete sequence.
  • Skin tone is stored as a separate property for clarity, but it is also already part of the emoji_char when applied. On load, the skin_tone property is used to reconstruct the correct code point sequence if needed.
  • Emoji rendering depends on the platform's emoji font. A project with emoji may look different on different operating systems. This is documented behavior.
  • The emoji_name is stored for display purposes and search. It is not required for rendering (the emoji_char is sufficient).

Acceptance Criteria

Numbered Step Tool

  1. Click-to-place creates a numbered badge at the click position with the correct sequential number.
  2. Rapid clicking places sequential numbers (1, 2, 3, ...) without requiring any intermediate steps.
  3. Click-and-drag allows custom sizing. The badge scales correctly.
  4. All 8 badge shapes render correctly with the number centered and legible.
  5. Auto font sizing produces readable text at all badge sizes from 16px to 128px.
  6. Display modes work correctly: Number (1, 2, 3), Letter (A, B, C), Roman (I, II, III), Custom Text.
  7. Changing Starting Number in the Tool Options Bar correctly sets the next placed number.
  8. "Renumber All Steps" correctly sorts by position and reassigns sequential numbers. The operation is fully undoable.
  9. Double-click inline editing allows changing the number/text and label. Tab switches between number and label fields.
  10. Label line feature renders correctly at all four positions with optional background pill.
  11. Pin badge shape correctly anchors at the pin point (bottom of tail).
  12. Shadow renders correctly for all badge shapes.
  13. Steps on locked/hidden layers cannot be placed.

Stamp / Sticker Tool

  1. The stamp library panel opens and displays all built-in stamps organized by category.
  2. Search correctly filters stamps by name and tags.
  3. Click-to-place creates a stamp at the click position at the configured size.
  4. Click-and-drag allows custom sizing with uniform scaling.
  5. Colorizable stamps correctly recolor when stamp_color is changed. Non-colorizable stamps are unaffected.
  6. Secondary color substitution works for stamps with dual-color regions.
  7. Flip horizontal and vertical produce correct mirrored rendering.
  8. Double-click opens the stamp library for replacement. Replacement is undoable.
  9. Custom stamps can be imported (SVG files), are stored in the user directory, and appear in the Custom tab.
  10. Project save embeds custom stamps. Projects with embedded stamps open correctly on systems without those custom stamps.
  11. Built-in stamps are not embedded in the project file (reference by ID only).
  12. All stamps render crisply at zoom levels from 10% to 3200%.
  13. Missing stamps (referenced but not found) show a placeholder icon rather than crashing.

Emoji Tool

  1. The emoji picker opens and displays emoji organized by Unicode standard categories.
  2. Search correctly filters emoji by name and keywords.
  3. Recent emoji section shows the last 24 used emoji.
  4. Click-to-place creates an emoji at the click position at the configured size.
  5. Emoji render correctly using the platform's emoji font at all sizes from 16px to 256px.
  6. Skin tone selection works for applicable emoji. The selected tone is remembered for the session.
  7. Flip horizontal and vertical produce correct rendering.
  8. Double-click opens the emoji picker for replacement. Replacement is undoable.
  9. On Linux, the bundled Noto Color Emoji font is used as a fallback when no system emoji font is detected.
  10. Emoji render correctly at all zoom levels.
  11. The emoji_char is correctly serialized and deserialized, including multi-codepoint sequences (ZWJ, skin tones).
  12. Opacity and shadow work correctly on emoji items.

Shared Behavior

  1. All three tools respect the active layer: cannot place on locked or hidden layers.
  2. All items are created with AddItemCommand and are fully undoable.
  3. All property changes produce ModifyPropertyCommand and are undoable.
  4. All items serialize and deserialize correctly with full property fidelity.
  5. Placement animation (scale-up for steps, pop-in for emoji) plays smoothly at 60 FPS.
  6. All items can be selected, moved, resized, and rotated via the Select tool after creation.
  7. All items support copy, cut, paste, and duplicate operations.
  8. Performance: placing 100 items of any type and selecting all 100 maintains 60 FPS.
