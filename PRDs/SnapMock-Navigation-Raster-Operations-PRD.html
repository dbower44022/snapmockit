Document Overview

Purpose

This document defines the detailed functional requirements for the navigation tools (Select/Move, Pan, Zoom) and raster operations (Raster Selection, Crop, Resize, Copy/Cut/Paste) in SnapMock. These tools collectively form the foundation for all canvas interaction. They must be implemented and tested before any annotation tools, as every annotation tool depends on selection, navigation, and clipboard behavior.

Scope

This PRD covers the complete interaction model for each tool: activation, mouse event handling, keyboard modifiers, visual feedback, state transitions, edge cases, error handling, and the undoable commands each tool produces. It references the Technical Architecture PRD for class structures and the General UI PRD for toolbar and options bar integration.

Dependencies

These tools depend on the following subsystems from the Technical Architecture PRD:

  • SnapScene and SnapView (Section 3.1): canvas rendering, coordinate transformation, zoom and pan infrastructure.
  • LayerManager (Section 3.2): active layer tracking, visibility and lock state queries.
  • ToolManager (Section 3.3): tool activation, event routing, temporary tool override.
  • SelectionManager (Section 3.4): selection state, multi-select, selection filtering.
  • TransformHandles (Section 3.4.2): resize, rotate, skew overlays on selected items.
  • CommandStack (Section 3.7): undo/redo for all state-changing operations.
  • ClipboardManager (Section 3.6): system and internal clipboard integration.
  • RasterRegionItem (Section 3.5.4): the item type created by raster cut/copy/paste.

The Select / Move tool is the default and most frequently used tool. It handles single and multi-item selection, moving items, and activating the TransformHandles for resize/rotate/skew. It is the only tool that interacts with TransformHandles directly.

Mouse Press Behavior

2.2.1 Left-click on empty canvas (no item under cursor):

  • If no modifier keys are held: deselect all currently selected items. Emit selectionCleared(). Begin rubber-band selection (see 2.3).
  • If Shift is held: do not deselect existing selection. Begin additive rubber-band selection.
  • If Ctrl is held: do not deselect existing selection. Begin toggle rubber-band selection.

2.2.2 Left-click on an unselected item:

  • Verify the item is on a visible, unlocked layer. If not, ignore the click (show forbidden cursor on hover).
  • If no modifier keys: deselect all, then select this item. Emit selectionChanged([item_id]).
  • If Shift is held: add this item to the current selection (additive select).
  • If Ctrl is held: add this item to the current selection (same as Shift for click; Ctrl distinction is used for toggle on already-selected items).
  • After selection, prepare for potential drag-move. Record the mouse press position as drag_start_pos. Do not begin the move yet (wait for mouse_move exceeding a drag threshold).

2.2.3 Left-click on an already-selected item:

  • If no modifier keys: keep the current selection (do not deselect others). Prepare for potential drag-move.
  • If Ctrl is held: deselect this item (toggle behavior). Emit selectionChanged() with updated list.
  • If Shift is held: no change (item is already selected).

2.2.4 Left-click on a TransformHandle:

  • Do not change the selection. Begin the corresponding transform operation (resize, rotate, or skew). Delegate to TransformHandles.begin_transform(handle_type, event).
  • See Section 2.5 for TransformHandle interaction details.

2.2.5 Right-click:

  • If clicking on an unselected item: select it first (single select), then show the item context menu.
  • If clicking on a selected item: show the item context menu without changing selection.
  • If clicking on empty canvas: show the canvas context menu.

Rubber-Band Selection

Rubber-band selection begins when the user presses the left mouse button on empty canvas and drags.

Visual Feedback:

  • A dashed rectangle (1px, accent color, 50% opacity fill) is drawn from the mouse press position to the current mouse position.
  • The rectangle updates in real-time as the mouse moves.
  • Items whose shapes intersect the rectangle are temporarily highlighted (outline glow) to preview the selection.

On Mouse Release:

  • Calculate all items whose shape() intersects the rubber-band rectangle.
  • Filter out items on hidden or locked layers.
  • If no modifier: these items become the new selection (replacing any previous selection).
  • If Shift was held during drag: add these items to the existing selection (union).
  • If Ctrl was held during drag: toggle these items in the selection (XOR - items that were selected become deselected, items that were not selected become selected).
  • Emit selectionChanged() with the final selection set.
  • Remove the rubber-band rectangle overlay.

Minimum Drag Threshold:

If the mouse is released within 3 pixels of the press position, treat it as a click (not a rubber-band drag). Apply click behavior from Section 2.2.1.

Move Operation

Moving begins when the user presses on a selected item and drags beyond the drag threshold (3 pixels).

During Drag:

  • Move all selected items by the delta between the current mouse position and drag_start_pos.
  • Movement is applied in real-time (items visually move as the mouse drags).
  • If Shift is held during drag: constrain movement to the axis with the largest delta (horizontal-only or vertical-only). The constraint axis is determined by the first 10 pixels of drag movement and then locked.
  • If Snap to Grid is enabled: snap the primary item's position to the nearest grid intersection. All other selected items maintain their relative offsets.
  • Display a tooltip near the cursor showing the delta: "ΔX: +15 ΔY: -8" (pixels from original position).

On Mouse Release:

  • Calculate the total delta from the original positions (recorded at mouse press).
  • If the delta is (0, 0) (items returned to original position), do not push a command.
  • Otherwise, push a MoveItemsCommand to the CommandStack with: item_ids, delta_x, delta_y.
  • The command stores original positions for undo.

Keyboard Nudge:

  • Arrow keys nudge all selected items by 1 pixel in the arrow direction.
  • Shift + Arrow keys nudge by 10 pixels.
  • Each nudge pushes a MoveItemsCommand. Consecutive nudges in the same direction within 500ms are merged into a single command (using merge_with()).

TransformHandle Interactions

2.5.1 Resize via Corner Handles:

  • Dragging a corner handle resizes the selection bounding box. All selected items are scaled proportionally relative to the opposite corner (the anchor point).
  • Default behavior: free resize (aspect ratio is not preserved).
  • Shift held: constrain to original aspect ratio.
  • Alt held: resize from center (both the dragged corner and the opposite corner move symmetrically).
  • Shift + Alt: constrain aspect ratio and resize from center.
  • Minimum size: items cannot be resized below 1x1 pixel. If the drag would result in a smaller size, clamp to 1x1.
  • Visual feedback: display the current width and height near the handle being dragged.

2.5.2 Resize via Edge Midpoint Handles:

  • Dragging a top or bottom midpoint handle resizes vertically only.
  • Dragging a left or right midpoint handle resizes horizontally only.
  • Shift held: no effect (aspect ratio constraint does not apply to single-axis resize).
  • Alt held: resize from center.
  • Ctrl held: apply skew transform instead of resize (see 2.5.4).

2.5.3 Rotate via Rotate Handle:

  • The rotate handle is a circular handle positioned 30 pixels above the top-center of the bounding box, connected by a thin line.
  • Dragging the rotate handle rotates all selected items around the center of the bounding box.
  • Default: free rotation (continuous angle).
  • Shift held: snap rotation to 15-degree increments (0, 15, 30, 45, 60, 75, 90, ...).
  • Visual feedback: display the current rotation angle near the handle (e.g., "45.0°"). A dashed line from the center to the handle shows the current angle.
  • The rotation pivot point is always the center of the selection bounding box.

2.5.4 Skew via Ctrl + Edge Midpoint Drag:

  • When Ctrl is held and an edge midpoint handle is dragged, the opposite edge remains fixed and the dragged edge slides parallel to itself.
  • Top/bottom edge drag: horizontal skew.
  • Left/right edge drag: vertical skew.
  • Visual feedback: the bounding box transforms into a parallelogram preview.

2.5.5 Transform Command:

  • On mouse release after any transform (resize, rotate, skew), push a TransformItemCommand to the CommandStack.
  • The command stores: item_ids, original transform matrices, new transform matrices.
  • Undo restores the original transforms. Redo re-applies the new transforms.

Double-Click Behavior

  • Double-click on a TextItem: enter inline text editing mode (delegate to TextTool).
  • Double-click on a CalloutItem: enter inline text editing mode for the callout text.
  • Double-click on a RasterRegionItem: zoom to fit the entire canvas in the viewport (equivalent to Ctrl+0). If the view is already at fit-to-window zoom, reset to 100% zoom centered on the canvas (equivalent to Ctrl+1). This matches the double-click-on-empty-canvas behavior, since raster regions have no inline editing mode.
  • Double-click on any other item: select only that item (deselect all others) and open the Property Panel scrolled to its properties.
  • Double-click on empty canvas: if the current zoom level is not “fit to window,” zoom to fit the entire canvas in the viewport (equivalent to Ctrl+0). If the view is already at fit-to-window zoom, reset to 100% zoom centered on the canvas (equivalent to Ctrl+1). This provides a quick toggle between overview and actual-size views.

Delete Behavior

  • Pressing Delete or Backspace with items selected: remove all selected items. Push a MacroCommand containing a RemoveItemCommand for each item.
  • If the selection includes items on locked layers, those items are silently skipped (not deleted).
  • After deletion, emit selectionCleared().

Tool Options Bar Content

  • When no items are selected: display "No selection" in gray text.
  • When items are selected: display "Selection: N item(s)" and the bounding box dimensions ("W: 200 H: 150").
  • When 2+ items are selected: additionally show quick alignment buttons (Align Left, Center, Right, Top, Middle, Bottom) and distribute buttons (Horizontal, Vertical).
  • All alignment/distribution buttons trigger their respective commands from the Arrange menu.

The Pan tool allows the user to scroll the canvas viewport by clicking and dragging. It is most commonly accessed as a temporary tool override by holding the Space bar while another tool is active.

Activation Modes

3.2.1 Permanent Activation:

  • Click the Pan tool in the Left Tool Palette, or select it from the Tools menu.
  • The tool remains active until another tool is selected.
  • Cursor changes to Open Hand.

3.2.2 Temporary Activation (Space Bar):

  • Holding the Space bar temporarily activates the Pan tool regardless of the currently active tool.
  • The previous tool is saved. On Space release, the previous tool is restored.
  • If the user is in the middle of a tool operation (e.g., drawing a rectangle), Space is ignored to prevent interruption.
  • The cursor changes to Open Hand while Space is held.
  • If the user presses Space and then presses the left mouse button, pan behavior begins. Releasing Space while still dragging continues the pan until the mouse button is released. After both are released, the previous tool is restored.

3.2.3 Middle Mouse Button:

  • Pressing and holding the middle mouse button activates pan behavior regardless of the active tool.
  • This works even during other tool operations (it does not interrupt the active tool's state).
  • Cursor changes to Closed Hand during the drag.
  • On release, the active tool resumes with no state change.

Mouse Event Handling

Mouse Press (Left button, when Pan tool is active):

  • Record the current viewport scroll position and mouse screen position as pan_start.
  • Change cursor to Closed Hand.

Mouse Move (dragging):

  • Calculate the delta between the current mouse screen position and pan_start.
  • Scroll the viewport by this delta (using QGraphicsView.horizontalScrollBar() and verticalScrollBar(), or QGraphicsView.translate()).
  • The movement is 1:1 (pixel-perfect tracking of the mouse movement).
  • This must be smooth and responsive at 60 FPS.

Mouse Release:

  • Change cursor back to Open Hand.
  • Pan is complete. No command is pushed to the CommandStack (panning is not undoable).

Scroll Wheel Behavior

  • Without Ctrl: vertical scroll wheel scrolls the viewport vertically. Shift + scroll wheel scrolls horizontally.
  • With Ctrl: scroll wheel triggers zoom (see Zoom Tool, Section 4).
  • Scroll speed: 3 lines per wheel notch (configurable in Preferences).

Keyboard Pan (Arrow Keys)

When no items are selected, the arrow keys pan the viewport instead of nudging items. This provides a quick, hands-on-keyboard method for navigating a zoomed-in canvas without switching tools or holding modifier keys.

Pan Distances:

  • Arrow key (no modifier): pan the viewport by one scroll step (equivalent to one scroll wheel notch, default 3 lines) in the arrow direction.
  • Shift + Arrow key: pan the viewport by half the viewport width (for Left/Right) or half the viewport height (for Up/Down). This allows the user to quickly traverse large distances across a zoomed-in canvas.

Conditions and Edge Cases:

  • Arrow key pan is only active when no items are selected. When items are selected, arrow keys revert to their standard nudge behavior (Section 2.4).
  • Arrow key pan works regardless of the active tool (Select, Pan, Zoom, etc.), as long as no items are selected and no text input field has focus.
  • If the viewport is already at the edge of the pasteboard in the arrow direction, the key press has no visible effect (the pan is clamped, consistent with unlimited pasteboard scrolling from Section 3.8).
  • Pan via arrow keys is not recorded in the undo history (consistent with all other pan methods).

Auto Edge Scroll

When the user is performing any drag operation and the cursor reaches the edge of the viewport, the canvas automatically pans in that direction. This allows the user to move items, draw selections, and perform other drag operations across a zoomed-in canvas in a single continuous gesture without releasing the mouse.

Applicable Operations:

  • Moving items with the Select tool (Section 2.4).
  • Rubber-band selection (Section 2.3).
  • Transform handle dragging: resize, rotate, and skew (Section 2.5).
  • Drawing a raster selection rectangle (Section 5.3).
  • Drawing a freeform or polygonal lasso selection (Section 6.2, 6.3).
  • Moving or resizing a raster selection marquee (Section 5.4).
  • Drawing a crop region (Section 7.4).
  • Moving or resizing a crop region via handles (Section 7.5).

Trigger Zone and Speed:

  • The auto-scroll trigger zone is the outermost 20 pixels of the viewport on each edge (top, bottom, left, right). When the cursor enters this zone during a qualifying drag operation, scrolling begins.
  • Scroll speed is proportional to how deep the cursor is within the trigger zone. At the inner edge of the zone (20px from viewport edge), scrolling is slow (approximately 2 pixels per frame). At the outermost pixel of the viewport, scrolling is fast (approximately 15 pixels per frame). This provides fine control near the boundary and rapid traversal when the cursor is pushed hard against the edge.
  • Scrolling operates on a 16ms timer (approximately 60 FPS) that is started when the cursor enters the trigger zone and stopped when the cursor leaves the zone or the drag operation ends.
  • Corner zones (where two edges meet) scroll diagonally, combining the horizontal and vertical scroll speeds.

Behavior During Scroll:

  • The active drag operation continues to update as the viewport scrolls. For item moves, the items move with the scroll so the cursor-to-item offset remains constant. For selections and crop regions, the selection area expands as the viewport pans to reveal more canvas.
  • Visual feedback: the viewport scrolls smoothly. No additional cursor change or overlay is shown (the existing drag cursor remains).
  • Auto-scroll respects the pasteboard bounds. Scrolling continues into the pasteboard area the same way manual pan does (unlimited).

Edge Cases:

  • If the canvas is fully visible (zoom level is at or below fit-to-window), auto edge scroll is disabled because there is nothing to scroll to.
  • If the cursor moves outside the viewport entirely (e.g., onto a second monitor or the OS taskbar), auto-scroll continues at maximum speed in the direction the cursor exited until the mouse button is released or the cursor re-enters the viewport.
  • Auto edge scroll does not apply to the Pan tool itself (dragging with the Pan tool already provides direct viewport movement).

Trackpad Gesture Support (macOS)

  • Two-finger drag: pan the viewport (same as middle-mouse-button pan).
  • Pinch: zoom in/out (delegates to Zoom Tool behavior).
  • These gestures should work regardless of the active tool.

Edge Cases

  • Panning beyond the canvas bounds is allowed. The pasteboard area (gray background) is infinitely scrollable in all directions.
  • After panning far from the canvas, the user can return via Home key (pan to origin) or Ctrl+0 (fit to window).
  • Pan does not affect the scene or any items. It is purely a viewport transformation.

Zoom Levels

SnapMock supports zoom levels from 10% to 3200%. The zoom step progression follows a perceptual scale where each step feels approximately equal in visual change:

10%, 15%, 20%, 25%, 33%, 50%, 67%, 75%, 100%, 125%, 150%, 200%, 250%, 300%, 400%, 500%, 600%, 800%, 1200%, 1600%, 2400%, 3200%

Custom zoom levels (typed into the zoom dropdown) are allowed at any integer percentage. The zoom step shortcuts (Ctrl++, Ctrl+-) always jump to the nearest predefined step.

Zoom Methods

4.3.1 Ctrl + Scroll Wheel (Primary Method):

  • This is the most common zoom method and works regardless of the active tool.
  • Scroll up: zoom in one step. Scroll down: zoom out one step.
  • Zoom center point: the zoom is centered on the cursor position. The scene point under the cursor should remain under the cursor after zooming. This provides intuitive zoom-to-point behavior.
  • Smooth animated transition: each zoom step animates over 100ms using QPropertyAnimation on the view's transform. If the user scrolls rapidly, animations queue and blend smoothly.

4.3.2 Zoom Tool Click:

  • Left-click: zoom in one step, centered on the click position.
  • Alt + left-click: zoom out one step, centered on the click position. Right-click zooms out the same way (1.3: a second route where the desktop takes Alt+left-button).
  • Click and drag: draw a zoom rectangle. On release, zoom to fit the drawn rectangle in the viewport. This allows precise zoom-to-area.
  • The zoom rectangle is drawn with a dashed accent-color outline and a 10% opacity fill.

4.3.3 Keyboard Shortcuts:

ShortcutAction

4.3.4 Zoom Dropdown (Toolbar):

  • The editable combo box in the Main Toolbar shows the current zoom level (e.g., "150%").
  • Clicking the dropdown shows the predefined zoom levels as selectable options.
  • The user can type a custom integer percentage (e.g., "137") and press Enter to set it.
  • Invalid input (non-numeric, out of range) is rejected and the field reverts to the current zoom.

Zoom-Dependent Rendering

  • Below 100% zoom: items may appear aliased. Anti-aliasing is applied to smooth rendering.
  • At 100% zoom: pixel-perfect rendering (1:1 mapping between canvas pixels and screen pixels).
  • Above 100% zoom: individual pixels become visible. Item rendering remains smooth (vector items use QPainter's sub-pixel rendering).
  • Above 800% zoom (configurable): a pixel grid overlay is drawn as 1px lines at 30% opacity delineating individual canvas pixels. This aids precise pixel-level work.
  • Rulers tick marks and labels adapt to zoom level (fewer labels at low zoom, more at high zoom) to remain readable.

Zoom Animation

  • All zoom transitions are animated over 100ms using an ease-out curve.
  • If a new zoom is triggered during an animation, the current animation is replaced (not queued) with a new animation from the current intermediate state to the new target.
  • Animation can be disabled in Preferences for users who prefer instant zoom.

The Raster Selection tool allows the user to select a rectangular region of pixels from the canvas. This is the primary mechanism for the UI mockup workflow: selecting a piece of a screenshot, cutting or copying it, and pasting it as a movable element.

Selection States

The raster selection tool has three distinct states:

StateDescriptionTransitions
IdleNo selection exists. The tool is waiting for the user to draw a selection.Mouse press on canvas → Drawing
DrawingThe user is actively dragging to define a selection rectangle.Mouse release → Active Selection
Active SelectionA selection marquee (marching ants) is visible. The user can manipulate the selection before committing.Press Enter or double-click inside → Commit. Drawing a Selection

Mouse Press (on canvas with no active selection):

  • Record the press position as selection_origin (in canvas coordinates).
  • If Fixed Size is enabled in the Tool Options Bar, the selection size is predetermined. The press position is the top-left corner (or center if Alt is held).
  • Transition to Drawing state.

Mouse Move (dragging during Drawing state):

  • Calculate the selection rectangle from selection_origin to the current mouse position.
  • Draw the selection rectangle as a marching-ants dashed outline (animated, 2px dashes alternating black and white, cycling at 200ms intervals).
  • Display selection dimensions near the cursor: "W: 320 H: 240" in a small tooltip.
  • Modifier keys during drag: Shift held: constrain to a square (width = height). The constraint uses the larger of the two dimensions. Alt held: draw from center (selection_origin is the center, not the corner). Both: square from center.
  • If Snap to Grid is enabled, snap the selection edges to grid intersections.
  • The selection rectangle is clipped to the canvas bounds (cannot extend beyond the canvas).

Mouse Release (end of Drawing):

  • If the selection area is less than 4 square pixels (essentially a click), cancel the selection and return to Idle.
  • Otherwise, transition to Active Selection state. The marching-ants animation continues.
  • Place resize handles (8 handles: 4 corners + 4 edge midpoints) on the selection marquee.

Active Selection Manipulation

5.4.1 Move Marquee:

  • Click inside the selection rectangle and drag to move the selection marquee without affecting pixels.
  • This allows repositioning the selection before performing copy/cut.
  • Shift constrains movement to horizontal or vertical axis.
  • The selection is clipped to canvas bounds.

5.4.2 Resize Marquee:

  • Drag any of the 8 handles to resize the selection.
  • Shift constrains to square (on corner handles).
  • The selection is clipped to canvas bounds.

5.4.3 Replace Selection:

  • Clicking outside the selection (on canvas) cancels the current selection and immediately begins a new selection drag from that point.
  • This provides a seamless workflow: you don't need to explicitly press Escape before drawing a new selection.

Pixel Operations on Active Selection

5.5.1 Copy (Ctrl+C):

  • Composite the pixel content within the selection rectangle from the configured source (active layer, all visible layers, or a specific layer).
  • Apply feather if configured (gaussian blur on the alpha channel at the edges).
  • Place the resulting QImage on both: the internal clipboard (with metadata: source_rect, source_layer_id, feather amount) and the system clipboard as a PNG image (for interoperability).
  • The selection remains active after copy.
  • No command is pushed (copy alone does not modify the document).

5.5.2 Cut (Ctrl+X):

  • Perform the same pixel capture as Copy.
  • Additionally, erase the pixels within the selection rectangle on the source layer(s). The erased area becomes transparent (alpha = 0) or fills with the canvas background color (configurable in Preferences: "Cut fills with transparency" checkbox, default: transparency).
  • If the source is "All Visible Layers," the cut only erases from the active layer (not all layers).
  • Push a RasterCutCommand to the CommandStack. The command stores: the original pixel data of the erased area (for undo), the selection rect, the source layer ID.
  • The selection is dismissed after cut (return to Idle state).

5.5.3 Paste (Ctrl+V, from Raster Selection context):

  • If the internal clipboard contains raster data from a raster selection copy/cut: create a new RasterRegionItem with the clipboard pixel data.
  • Position the new item at the current cursor position on the canvas. If Ctrl+Shift+V is used (Paste in Place), paste at the original source location.
  • Add the item to the active layer.
  • Push an AddItemCommand to the CommandStack.
  • Automatically switch to the Select tool and select the newly pasted item (so the user can immediately move it).
  • Dismiss the raster selection marquee (return to Idle).

5.5.4 Commit Selection (Enter or Double-Click inside):

  • Performs the same operation as Copy + Paste: captures the pixel content within the selection, creates a RasterRegionItem on the active layer offset from the selection position by 10% of the selection region’s width to the right and 10% of the selection region’s height downward. This offset ensures the new item is visually distinguishable from the original source pixels beneath it.
  • Does NOT erase the source pixels (unlike Cut).
  • Switches to Select tool with the new item selected.
  • This is the quick workflow for "grab a piece of the screenshot and make it movable."

Marching Ants Rendering

  • The marching ants are rendered as an overlay on top of all scene content (highest z-order, not part of any layer).
  • Pattern: alternating 4px black and 4px white dashes on the selection outline.
  • Animation: the dash pattern offset advances by 1px every 100ms, creating the illusion of movement.
  • The area outside the selection is dimmed with a semi-transparent overlay (10% black) to visually isolate the selected region.
  • When the selection is being moved or resized, the dimming overlay updates in real-time.

Edge Cases

  • Selection on a fully transparent area: copy/cut captures transparent pixels. The resulting RasterRegionItem appears invisible but exists as a valid item.
  • Selection that extends beyond canvas bounds during drawing: clamp the selection to canvas bounds.
  • Switching tools while an active selection exists: the selection is dismissed (return to Idle). A warning is not shown; this is expected behavior.
  • Undo after Cut: restores the erased pixels to the source layer. The RasterRegionItem created by a subsequent paste is not affected (it's a separate undo step).
  • Very large selections (e.g., full 4K canvas): the copy operation may take a moment. Show a brief progress indicator in the status bar for operations taking more than 200ms.

The Freeform / Lasso selection tool works identically to the Rectangle Raster Selection tool (Section 5) in terms of pixel operations (copy, cut, paste, commit) but defines a non-rectangular selection boundary.

Freeform Mode (Default)

Drawing:

  • Mouse press begins the path at the press position.
  • Mouse drag continuously appends points to the path (sampled at the mouse move event rate).
  • The path is rendered as a solid accent-color line (2px) as the user draws.
  • Mouse release auto-closes the path: a straight line is drawn from the last point to the first point.
  • The closed path becomes the selection boundary. Marching ants animate along the path.
  • Path smoothing is applied based on the Smoothing slider value. At 0%, the raw sampled points are used. At 100%, an aggressive Bezier curve simplification is applied to produce smooth curves.
  • If the resulting closed path has an area less than 16 square pixels, the selection is canceled.

Polygonal Mode

Drawing:

  • Each left-click adds a vertex to the polygon path.
  • A preview line is drawn from the last vertex to the current cursor position.
  • Shift constrains the preview line to 0/45/90 degree angles.
  • Double-click or pressing Enter closes the polygon (connects the last vertex to the first).
  • Pressing Escape during drawing cancels the polygon and returns to Idle.
  • Right-click removes the last vertex (undo last point).
  • Minimum 3 vertices required to form a valid selection.

Selection Mask & Pixel Operations

  • The freeform/polygonal path defines an alpha mask. Pixels inside the path are fully selected (alpha = 255). Pixels outside are not selected (alpha = 0).
  • When feathering is applied, the alpha mask is blurred at the edges by the feather radius.
  • When anti-aliasing is enabled, edge pixels have partial alpha values for smooth boundaries.
  • Copy/Cut/Paste operations use this mask to extract pixels. The resulting RasterRegionItem stores both the pixel data (QPixmap) and the alpha mask (QBitmap).
  • The RasterRegionItem's boundingRect() is the bounding box of the freeform path. Pixels outside the mask are transparent.

Active Selection Manipulation

  • Unlike the rectangle selection, the freeform selection cannot be resized by handles after drawing (the shape is too complex for simple handle-based editing).
  • The selection marquee can be moved by clicking inside and dragging (same as rectangle selection).
  • Replacing the selection works the same: click outside to cancel and start a new path.

  1. Record the crop rectangle in canvas coordinates.
  2. Resize the canvas to the crop rectangle dimensions.
  3. Reposition all items: subtract the crop rectangle's top-left corner from every item's position, so items maintain their visual position relative to the crop area.

  5. Remove items that are entirely outside the crop boundary (they would be invisible anyway).

  • Pressing Escape or switching to another tool cancels the crop.
  • The crop overlay is removed. No changes are made to the canvas or items.
  • If switching tools, the crop is silently canceled (no confirmation dialog).

Copy, Cut, Paste & Duplicate Operations

This section defines the clipboard operations that work across all tools and item types. Raster-selection-specific clipboard behavior is covered in Section 5.5; this section covers the general case for vector annotation items and mixed selections.

Copy (Ctrl+C)

When vector items are selected (via Select tool):

  1. Serialize all selected items to JSON (the same format used by project serialization).
  2. Package the JSON as MIME type "application/x-snapmock-items" on the internal clipboard.
  3. Additionally, render the selected items to a QImage (with transparent background) and place it on the system clipboard as a PNG. This enables pasting into other applications.
  4. Store metadata on the internal clipboard: item_ids, original positions, source layer_id.
  5. No command is pushed (copy is non-destructive).

When a raster selection is active (marching ants visible):

See Section 5.5.1 (Raster Selection Copy). The raster pixels take priority over any vector item selection.

When nothing is selected:

Ctrl+C is a no-op. The menu item is grayed out.

Cut (Ctrl+X)

When vector items are selected:

  1. Perform Copy (Section 9.1).
  2. Delete all selected items from the scene and their respective layers.
  3. Push a MacroCommand containing: a CopyToClipboardCommand (for redo state) and a RemoveItemCommand for each deleted item.
  4. Emit selectionCleared().

When a raster selection is active:

See Section 5.5.2 (Raster Selection Cut).

Paste (Ctrl+V)

9.3.1 Internal Clipboard Has SnapMock Items:

  1. Deserialize the JSON from the internal clipboard.
  2. Create new instances of each item with new UUIDs (deep clone).
  3. Position the items at the current cursor position on the canvas. The top-left corner of the pasted items’ bounding box is placed at the cursor location.
  4. If the original items came from a different layer than the currently active layer, paste them onto the active layer.
  5. Add all items to the active layer and scene.
  6. Push a MacroCommand containing an AddItemCommand for each item.
  7. Select all newly pasted items. Switch to Select tool if not already active.
  8. Each subsequent Ctrl+V paste places items at the current cursor position. No automatic cascade offset is applied since the user controls placement via the cursor.

9.3.2 Internal Clipboard Has Raster Data:

See Section 5.5.3 (Raster Selection Paste).

9.3.3 System Clipboard Has an Image (No Internal Data):

  1. Read the image from the system clipboard (QClipboard.image()).
  2. Create a new RasterRegionItem with the image as its pixmap.
  3. Position at the current cursor position on the canvas.
  4. Add to the active layer.
  5. Push an AddItemCommand.
  6. Select the new item. Switch to Select tool.

9.3.4 System Clipboard Has Text (No Internal or Image Data):

  1. Create a new TextItem with the clipboard text as its content.
  2. Use default text properties (font, size, color from Preferences).
  3. Position at the current cursor position on the canvas.
  4. Add to the active layer.
  5. Push an AddItemCommand.
  6. Select the new item. Switch to Select tool.

9.3.5 Clipboard Is Empty:

Ctrl+V is a no-op. The menu item is grayed out.

Paste in Place (Ctrl+Shift+V)

  • Same as Paste, except items are placed at their original positions (not at the cursor position).
  • Useful for copying items between layers: copy on Layer A, switch to Layer B, paste in place.
  • If the original position data is not available (e.g., pasting from system clipboard), behaves identically to regular Paste.

Duplicate (Ctrl+D)

  • A shortcut that combines Copy and Paste in Place with a small offset.
  • Clone all selected items with new UUIDs.
  • Place the clones offset from the originals by 10% of the selection bounding box’s width to the right and 10% of its height downward. This ensures the duplicates are visually distinguishable from the originals.
  • Add to the same layer as the originals.
  • Push a MacroCommand containing AddItemCommands for each clone.
  • Select the clones (deselect originals).
  • Subsequent Duplicate operations (without moving in between) continue to offset by the same 10% increment from the last duplicate position (not from the original).

Clipboard Priority & MIME Types

When pasting, the clipboard is checked in this order:

  1. Internal clipboard: "application/x-snapmock-items" (vector items)
  2. Internal clipboard: "application/x-snapmock-raster" (raster selection data)
  3. System clipboard: image data (QClipboard.image())
  4. System clipboard: text data (QClipboard.text())
  5. If none of the above: paste is disabled.

The internal clipboard takes priority because it contains richer data (item properties, layer info, etc.). Pasting from external sources creates new items with default properties.

Cross-Instance Paste

Copying from one SnapMock window and pasting into another uses the system clipboard (PNG or text). Internal clipboard data is per-process and does not transfer between SnapMock instances. This means vector items copied between instances will arrive as raster images, not editable vector objects. A future enhancement could use a custom MIME type on the system clipboard to preserve vector data across instances.

Layer State Changes During Tool Operations

  • If the active layer is locked while the user has items selected on that layer: immediately deselect those items. The user cannot interact with them until the layer is unlocked.

  • If the active layer is deleted while a raster selection is active on it: cancel the raster selection.
  • If the active layer changes (user clicks a different layer in Layer Panel) while a raster selection is active: cancel the raster selection.
  • If the active layer changes while items are selected: keep the selection if the selected items are on visible, unlocked layers. Deselect any items that are on the newly hidden/locked layer.

Undo/Redo During Tool Operations

  • Pressing Ctrl+Z while in the middle of a draw operation (raster selection being drawn, crop being drawn): cancels the current operation first, then performs the undo.
  • Pressing Ctrl+Z with an active raster selection (marching ants): dismisses the selection first. A second Ctrl+Z performs the actual undo.
  • Pressing Ctrl+Z with a crop overlay: dismisses the crop first.
  • Pressing Ctrl+Z while dragging items: cancels the drag (items snap back to pre-drag positions). No command is pushed. A second Ctrl+Z undoes the previous command.

Multi-Monitor & Focus

  • If the application loses focus (user switches to another application) while holding Space (pan) or Ctrl+Space (zoom): treat it as a key release event. Return to the previous tool.
  • If the application loses focus during a drag operation: treat it as a mouse release. Finalize or cancel the operation as appropriate.
  • Keyboard shortcuts only work when the main window or its child widgets have focus.

Acceptance Criteria

Select / Move Tool

  1. Single-click selects an item. Shift+click adds to selection. Ctrl+click toggles. Click on empty canvas deselects all.
  2. Rubber-band selection selects all items whose shapes intersect the rectangle. Shift and Ctrl modifiers work as specified.
  3. Dragging selected items moves them. Shift constrains to one axis. Snap to grid works when enabled.
  4. Arrow key nudge moves items by 1px (10px with Shift). Consecutive nudges merge into a single undo step.
  5. TransformHandles appear around the selection bounding box. All 8 resize handles, the rotate handle, and skew (Ctrl+edge drag) work as specified.
  6. All move and transform operations produce correct undoable commands. Undo restores exact original state.
  7. Items on locked or hidden layers cannot be selected.
  8. Double-click on TextItem enters text editing mode.
  9. Double-click on empty canvas toggles between fit-to-window zoom and 100% zoom.

Pan / Hand Tool

  1. Clicking and dragging pans the viewport with 1:1 mouse tracking at 60 FPS.
  2. Space bar temporarily activates pan without changing the active tool. Release returns to previous tool.
  3. Middle mouse button pans without changing active tool, even during other operations.
  4. Panning beyond canvas bounds into the pasteboard is smooth and unlimited.
  5. Pan is not recorded in the undo history.
  6. Arrow keys pan the viewport when no items are selected. Shift+Arrow pans by half the viewport dimension. Arrow keys revert to nudge behavior when items are selected.
  7. Auto edge scroll activates when the cursor enters the outermost 20px of the viewport during any drag operation (item move, rubber-band, transform handle, raster selection, crop). Scroll speed increases as the cursor approaches the viewport edge. Scrolling stops when the cursor leaves the trigger zone or the drag ends.

Zoom Tool

  1. Ctrl+scroll wheel zooms in/out centered on the cursor position. The scene point under the cursor remains stable.
  2. Zoom range is 10% to 3200%. All predefined zoom steps are reachable.
  3. Ctrl+0 fits the canvas in the viewport. Ctrl+1 sets 100% zoom.
  4. The zoom dropdown in the toolbar reflects the current zoom and accepts custom values.
  5. Zoom transitions are animated (100ms ease-out).
  6. Pixel grid overlay appears above 800% zoom.
  7. Zoom rectangle (drag with zoom tool) correctly zooms to the drawn area.

Raster Selection (Rectangle)

  1. Click-and-drag draws a rectangular selection with marching-ants animation.
  2. Shift constrains to square. Alt draws from center.
  3. Selection dimensions are displayed near the cursor during drawing.
  4. Active selection can be moved by dragging inside and resized via handles.
  5. Ctrl+C copies the selected pixels to clipboard (both internal and system).
  6. Ctrl+X cuts the pixels, leaving transparency, and the operation is undoable.
  7. Enter commits the selection as a RasterRegionItem on the active layer, offset by 10% of the selection region’s width to the right and 10% of its height downward from the original position.
  8. Escape cancels the selection.
  9. Pasting raster data creates a new RasterRegionItem at the current cursor position that can be moved with the Select tool.
  10. Feather and anti-alias options produce correct results on selection edges.

Raster Selection (Freeform / Lasso)

  1. Freeform mode: click-and-drag draws a freeform path. Release auto-closes the path.
  2. Polygonal mode: each click adds a vertex. Double-click closes the polygon.
  3. Path smoothing is applied according to the slider value.
  4. All pixel operations (copy, cut, paste, commit) produce correctly masked results.
  5. The alpha mask is preserved in the resulting RasterRegionItem.

Crop Canvas

  1. Activating the crop tool shows the crop overlay with dim area, handles, and optional rule-of-thirds grid.
  2. Crop region can be drawn, resized via handles, moved, and entered numerically.
  3. Aspect ratio lock constrains the crop proportions.
  4. Enter commits the crop: canvas resizes, items reposition, and out-of-bounds items are removed.
  5. The crop operation is fully undoable: undo restores the original canvas size, all item positions, and any clipped raster data.
  6. Escape cancels the crop with no changes.

Resize Canvas / Resize Image

  1. Resize Canvas dialog correctly expands/shrinks the canvas based on anchor position and fills new area with the selected color.
  2. Resize Image dialog scales all layers and items. Interpolation method selection produces visually correct results.
  3. Both operations are fully undoable.
  4. Progress indicators appear for operations taking longer than 500ms.
  5. Memory warnings appear for operations that would exceed reasonable memory bounds.

Copy / Cut / Paste / Duplicate

  1. Copy places both internal (JSON) and system (PNG) data on clipboard.
  2. Cut copies and then deletes items as a single undoable command.
  3. Paste from internal clipboard creates new items with new UUIDs at the current cursor position on the canvas.
  4. Paste in Place positions items at their original coordinates.
  5. Paste from system clipboard (image) creates a RasterRegionItem. Paste from system clipboard (text) creates a TextItem.
  6. Duplicate creates copies offset by 10% of the selection bounding box width/height on the same layer in a single undoable command.
  7. Clipboard priority order (internal items > internal raster > system image > system text) is respected.

Inter-Tool Interactions

  1. Switching tools during active raster selection or crop silently cancels the operation.
  2. Space bar pan override does not interrupt active drawing/dragging operations.
  3. Middle mouse button pan works during any tool state without interruption.
  4. Ctrl+Z during active operations cancels the operation before performing undo.
  5. Layer lock/hide during active selection correctly deselects affected items.

Performance

  1. Rubber-band selection renders at 60 FPS even with 100+ items in the scene.
  2. Raster selection copy/cut of a 4K region completes in under 500ms.
  3. Crop commit on a project with 50 items completes in under 1 second.
  4. Zoom animation maintains 60 FPS.
  5. Marching ants animation does not cause measurable CPU load when idle.
