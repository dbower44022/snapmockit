Document Overview

Purpose

This document defines the functional requirements for the SnapMock Library feature. The Library provides a rapid-capture workspace that automatically stores annotation files to a user-defined directory, decoupling the act of capturing and annotating from the overhead of manual file management. Users can capture many screenshots in quick succession, annotate them at their leisure, and later save or export finished work to permanent locations.

Scope

This PRD covers: the Library panel (dockable file browser), the Library menu in the main menu bar, capture-to-library auto-save workflow, tabbed multi-document editing, file management operations within the library, drag-and-drop import/export, multi-select batch operations, export from the library, and Preferences integration. This document does not redefine the .smk file format (covered in the Technical Architecture PRD) or the Export dialog (covered in the General UI PRD).

Dependencies

  • Technical Architecture PRD: .smk file format (Section 3.8), CommandStack, File I/O & Serialization.
  • General UI PRD: Main Window Layout, Menu Bar, Export Dialog, Preferences Dialog, Keyboard Shortcuts, Session Persistence.
  • Navigation & Raster Operations PRD: Capture and import workflows.

Library Concept

Purpose & Workflow

The Library is a quick work-in-progress storage mechanism. The core workflow is:

  • Capture a screenshot. It instantly appears in the Library as a .smk file.
  • Optionally annotate the capture immediately, or move on to capture the next screenshot.
  • Later, open the Library panel to browse all captured files.
  • Double-click a file to open it in a canvas tab for annotation.
  • When finished, export or save the file to a permanent location.

This workflow eliminates the friction of choosing file names and save locations during rapid capture sessions. All working files are kept in a single, organized directory.

Library Directory

The Library directory is a user-defined folder on disk where all auto-saved .smk files are stored. Configuration:

  • Default path: ~/SnapMock/Library/ (Linux/macOS) or %USERPROFILE%\SnapMock\Library\ (Windows). Created automatically on first launch if it does not exist.
  • User configurable: The library path is set in Preferences > Library (see Section 8) and displayed in the Library panel header.
  • Switching libraries: The user can open a different directory as the active library via the Library menu or the Library panel. Switching does not move or delete files in the previous library.
  • Moving a library: The user can move the entire library directory to a new location. SnapMock moves all files and updates the stored path.
  • Multiple libraries: Only one library directory is active at a time. The user switches between libraries by opening a different directory.

Auto-Save Behavior

The Library uses a continuous write-back strategy to ensure files are always up to date:

  • On capture: A new .smk file is immediately created in the library directory containing the captured raster image and an initial (empty) annotation JSON.
  • On every completed action: Whenever a command is pushed to the undo stack (any annotation operation: add item, move, resize, property change, delete, etc.), the annotation JSON files (layers.json, items.json, manifest.json) within the .smk archive are written back. Because these are small JSON files, the write is effectively instantaneous.
  • Raster data: The raster image (background layer PNG, raster region PNGs) is written once at capture time and only rewritten when a raster-level operation occurs (crop, resize image, raster cut/paste, flatten layers).
  • No explicit save required: Library files are always current. The traditional File > Save workflow is used only when saving a copy to a different location outside the library.
  • Crash safety: Because writes happen on every action, the maximum data loss in a crash is the last in-progress action (which was not yet committed to the undo stack).

Native File Format (.smk) Integration

Library files use the standard .smk format as defined in the Technical Architecture PRD (Section 3.8.1). The .smk ZIP archive contains manifest.json, layers.json, items.json, raster/ directory, thumbnails/ directory, and fonts/ directory. The Library adds no additional structures to the .smk format; library-specific metadata (such as the display name) is stored in manifest.json via an optional library_metadata field:

FieldTypeDescription
display_namestringUser-assigned display name for the file. Defaults to the auto-generated capture name. Updated when the user renames the file in the Library panel.
captured_atISO 8601 stringTimestamp of the original capture. Immutable after creation.
sourcestringOrigin of the file: "capture" (screen capture), "import" (imported image), "new" (blank canvas).

Library Panel

Panel Overview

The Library panel is a dockable panel (QDockWidget) that provides a visual file browser for all .smk files in the active library directory. It displays thumbnails or previews of library files, supports full file management operations, and allows the user to open files for editing by double-clicking.

Default PositionBottom edge of main window

Docking & Positioning

The Library panel follows the standard QDockWidget behavior established in the General UI PRD (Section 2.3):

  • Dockable to the left, right, top, or bottom edges of the main window.
  • Can be floated as an independent window (undocked) and dragged to any monitor.
  • Can be tabbed together with the Layer Panel or Property Panel if docked to the same edge.
  • Can be closed (hidden) via the panel's close button or the View menu. Re-opened via View > Show Library Panel.
  • Dragging the panel near a dock edge shows a blue highlight indicator of the dock target area.
  • Panel position, size, and dock state are saved and restored across sessions via QSettings.

Panel Layout

The Library panel is organized into three horizontal zones, from top to bottom:

Header Bar

  • Library path display: A read-only text label showing the current library directory path (truncated with ellipsis if too long). Hovering shows the full path in a tooltip.
  • Change Library button: A small folder icon button that opens a directory chooser dialog to switch to a different library folder.
  • View toggle: Two small icon buttons to switch between Grid View and Preview (List) View. The active view is highlighted.
  • Size slider: A small slider to adjust thumbnail/preview size (see Section 3.6).
  • Search bar: A text input field with a magnifying glass icon for filtering files by name (see Section 3.10).

Content Area

The scrollable area displaying library files in either Grid View or Preview List View. Supports folder navigation with a breadcrumb path or back button. When the library is empty, displays a centered message: "No files in library. Capture a screenshot or drag images here to get started."

Footer Bar

  • File count: "N files" (or "N files in M folders" if subfolders exist).
  • Library size: Total disk usage of the library directory (e.g., "248 MB"). Updated when files are added, removed, or modified.
  • Sort dropdown: A small dropdown to select the sort order (see Section 3.10).

Thumbnail Grid View

In Grid View, library files are displayed as a grid of thumbnail cards. Each card contains:

  • Thumbnail: A preview image of the annotation file rendered at the current thumbnail size. Thumbnails are generated from the thumbnails/ directory in the .smk file and cached in memory. If no thumbnail is available, a placeholder icon is shown.
  • File name: Displayed below the thumbnail, truncated with ellipsis if too long.
  • Modified date: Displayed below the file name in smaller, gray text (e.g., "Mar 1, 2026 2:23 PM").

Folder items display a folder icon with a small preview mosaic of the first 4 files inside. The folder name and item count ("12 items") are displayed below.

Preview List View

In Preview List View, library files are displayed as horizontal rows. Each row contains, from left to right:

  • Thumbnail: A square preview image at the current preview size.
  • File name: The display name of the file.
  • File size: The .smk file size on disk (e.g., "1.2 MB").
  • Date modified: Last modification timestamp.
  • Date captured: Original capture timestamp (from captured_at in manifest.json).

Columns are resizable. The user can click column headers to sort by that column.

Thumbnail / Preview Size

The size slider in the header bar controls the thumbnail and preview dimensions:

  • Grid View: Thumbnail size ranges from 80x80px (minimum) to 256x256px (maximum). Default: 128x128px. The grid reflows as the size changes.
  • Preview List View: Preview height ranges from 48px (minimum) to 128px (maximum). Default: 64px. Width scales proportionally.
  • The current size is saved and restored across sessions.

File Selection & Interaction

  • Single click: Selects the file (highlights it with the accent color). Deselects any previously selected file unless Ctrl or Shift is held.
  • Double-click: Opens the file in a new canvas tab for editing (see Section 4). If the file is already open in a tab, switches to that tab.
  • Double-click on folder: Navigates into the folder, updating the content area to show the folder's contents and updating the breadcrumb path.
  • Right-click: Opens the context menu (see Section 3.14).
  • Enter key: Opens the selected file(s) in canvas tabs.
  • F2 key: Begins inline rename of the selected file.
  • Delete key: Deletes the selected file(s) with confirmation dialog.

File Management Operations

The Library panel supports full file system operations within the library directory:

OperationBehavior
RenameInline rename: click on the file name (or press F2) to enter edit mode. The name field becomes an editable text input. Press Enter to confirm or Escape to cancel. The .smk file on disk is renamed accordingly. If the file is open in a tab, the tab title updates.
DeleteRemoves the file from the library as an undoable command. A confirmation dialog is shown: "Delete [filename]? The file will be moved to the system trash." If the file is open in a tab, the tab is closed first. Multi-select delete is supported, and a folder is deleted whole. The file first moves into a session trash folder, .trash/<session> at the library root, which the panel never lists and the size indicator never counts. Undo (Ctrl+Z in the panel) moves the file back to its original path, or to the next free name if that path is taken; undo does not reopen a closed tab. The file reaches the system trash only when the delete can no longer be undone: when its command leaves the undo stack (by the stack limit, by a newer command after an undo, or when the stack is cleared), when the window closes, when the library is switched or moved, and by a sweep at startup that clears session trash left by a session that did not close cleanly. Each window has its own session trash, so two windows on the same library never sweep each other's held deletes.
CopyCopies the selected file(s) to the internal clipboard. The files remain in the library.
PastePastes copied file(s) into the current folder. If a name conflict exists, the pasted file is renamed with a " (Copy)" suffix.
MoveDrag-and-drop a file onto a folder to move it. If the file is open in a tab, the file reference is updated silently.
New FolderCreates a new folder in the current directory with the name "New Folder" (or "New Folder (2)" etc. if a conflict exists). The folder name is immediately editable for renaming.

Folder Support

The Library supports user-created subdirectories within the library root for organizing files:

  • Folders appear as items in the grid or list view with a folder icon.
  • Double-clicking a folder navigates into it.
  • A breadcrumb path or back button in the content area header shows the current navigation depth and allows navigating back to parent folders.
  • The root of the breadcrumb is the library directory name (e.g., "Library > Screenshots > March").
  • Files can be moved between folders via drag-and-drop or cut/paste.
  • Empty folders can be deleted without confirmation. Folders with content show a confirmation dialog listing the item count.

Sorting & Searching

Sorting

The sort dropdown in the footer bar provides the following sort options:

  • Name (A-Z) / Name (Z-A)
  • Date Modified (Newest First) / Date Modified (Oldest First)
  • Date Captured (Newest First) / Date Captured (Oldest First)
  • File Size (Largest First) / File Size (Smallest First)

Folders always appear before files, sorted by the same criteria. The default sort order is Date Modified (Newest First). The selected sort order is saved and restored across sessions.

Searching

The search bar in the header filters the current view in real-time as the user types:

  • Filtering is case-insensitive and matches against the file display name.
  • The filter applies to the current folder only (does not search recursively into subfolders).
  • When a filter is active, the file count in the footer updates to show "N of M files" to indicate filtered results.
  • Clearing the search bar (or pressing Escape while focused in it) removes the filter and shows all files.

Library Size Indicator

The footer bar displays the total size of the library directory on disk. This is calculated by summing the sizes of all files in the library directory (including all subdirectories). The size is displayed in human-readable format (e.g., "248 MB", "1.3 GB"). The value is recalculated when files are added, removed, or modified, and on panel open. For large libraries, the calculation runs asynchronously to avoid blocking the UI.

Multi-Select

The Library panel supports selecting multiple files for batch operations:

  • Ctrl+click: Toggles individual file selection (add/remove from selection).
  • Shift+click: Selects a range of files from the last selected file to the clicked file.
  • Ctrl+A: Selects all files in the current folder (not including folders themselves).

Multi-select batch operations include: delete, move (drag to folder), export, copy, and open in tabs. The context menu adapts to show relevant multi-select actions when multiple files are selected.

Drag-and-Drop

Drag Into Library (Import)

  • Dragging image files (PNG, JPEG, BMP, TIFF, GIF, WebP) from the OS file manager into the Library panel imports them.
  • Each imported image is converted to a new .smk file: the image becomes the background layer, an empty annotation layer is created, and the file is saved to the current library folder.
  • The auto-naming convention is applied (see Section 6.2) using "Import" as the prefix instead of "Capture".
  • Dragging an existing .smk file into the library copies it to the current library folder.
  • A drop indicator (highlighted border around the panel) shows when a valid drop target is active.
  • Multiple files can be dragged in simultaneously.

Drag Out of Library (Export)

  • Dragging a file from the Library panel to the OS desktop or file manager exports a flattened PNG copy of the file to the drop location.
  • Dragging a file from the Library panel to the canvas area of SnapMock opens the file in a new tab (equivalent to double-click).
  • Multiple files can be dragged out simultaneously; each produces a separate PNG file.

Copy to Clipboard

  • Selecting a file and pressing Ctrl+C (or right-click > Copy to Clipboard) places a flattened PNG rendering of the file on the system clipboard, ready to paste into other applications.
  • This is distinct from the file-level Copy operation, which copies the .smk file for paste within the library.

Tabbed Editing

Tab Bar

When the Library feature is active, the canvas area gains a tab bar at the top that allows multiple .smk files to be open simultaneously. The tab bar appears above the canvas and below the Tool Options Bar.

  • Each open file is represented by a tab showing the file's display name.
  • The active tab is visually distinguished with the accent color and a slightly larger font weight.
  • Tabs are reorderable by dragging.
  • Each tab has a close button (X) on the right side.
  • If too many tabs are open to fit, overflow tabs are accessible via a dropdown chevron button at the right end of the tab bar.
  • The tab bar is hidden when only one file (or no file) is open.

Opening Files

  • Double-clicking a file in the Library panel opens it in a new tab.
  • If the file is already open, the existing tab is activated (no duplicate tabs).
  • File > Open also opens files in new tabs.
  • New captures automatically open in a new tab if the user has the "Auto-open captures" preference enabled (see Section 8.1).

Tab Behavior

  • Switching tabs: Clicking a tab switches the canvas to display that file. The Tool Options Bar, Property Panel, and Layer Panel all update to reflect the active file's state. The undo/redo stack is per-file; switching tabs changes the active undo stack.
  • Closing a tab: Clicking the close button on a tab closes that file. For library files, because continuous write-back keeps them saved, no save prompt is shown. For files opened from outside the library that have unsaved changes, the standard unsaved changes dialog is shown.
  • Window title: The window title shows the active tab's file name: [Filename] - SnapMock. For modified non-library files: *[Filename] - SnapMock.
  • Keyboard navigation: Ctrl+Tab cycles forward through open tabs. Ctrl+Shift+Tab cycles backward. Ctrl+W closes the active tab.
  • Middle-click: Middle-clicking a tab closes it (standard tab behavior).
  • Tab context menu: Right-clicking a tab shows: Close, Close Others, Close All, Close Tabs to the Right, Reveal in Library, Reveal in File Manager.

Continuous Write-Back

For files that reside in the library directory, the continuous write-back mechanism (Section 2.3) keeps them saved at all times. This means:

  • No asterisk (*) appears in the tab title for library files, since they are always saved.
  • Closing a tab for a library file never triggers an unsaved changes prompt.
  • The undo/redo history for each file is maintained in memory for the duration the tab is open. Closing and reopening a file resets the undo history.
  • If the user undoes actions in a library file, the write-back updates the .smk file to reflect the undo state. The redo stack remains available until the tab is closed or a new action branches the history.

Capture-to-Library Workflow

Capture Integration

When a screen capture is performed (via hotkey, system tray, or capture button), the captured image is immediately processed into the library:

  • A new .smk file is created in the current library folder (or root if no subfolder is navigated to).
  • The captured image is stored as the background layer raster in the raster/ directory of the .smk archive.
  • An empty annotation layer ("Annotations") is created above the background layer.
  • A thumbnail is generated and stored in the thumbnails/ directory.
  • The manifest.json is populated with the auto-generated file name, current timestamp as captured_at, source set to "capture", and the application version.
  • The file appears in the Library panel immediately (the panel refreshes its file list).
  • If the "Auto-open captures" preference is enabled, the file also opens in a new canvas tab.
  • A brief toast notification appears at the bottom of the screen: "Captured to Library: [filename]" with a clickable link to open the file.

Auto-Naming Convention

Auto-generated file names follow the pattern:

[Prefix]_[Date]_[Time].[ext]

Where:

  • Prefix: "Capture" for screen captures, "Import" for imported images, "Untitled" for new blank canvases.
  • Date: YYYY-MM-DD format.
  • Time: HH-MM-SS format (24-hour, using hyphens instead of colons for file system compatibility).
  • Extension: .smk

Example: Capture_2026-03-01_14-23-45.smk

If a name collision occurs (extremely unlikely given second-level precision), a numeric suffix is appended: Capture_2026-03-01_14-23-45_2.smk.

Import via Drag-and-Drop

External images dragged into the Library panel are imported using the same workflow as capture (Section 6.1), with these differences:

  • The prefix is "Import" instead of "Capture".
  • The source field in manifest.json is set to "import".
  • Multiple images can be dragged in simultaneously; each produces a separate .smk file.
  • Supported import formats: PNG, JPEG, BMP, TIFF, GIF, WebP.

Export

The Export dialog is defined by the General UI PRD (Section 11.2) and is delivered by the General UI implementation, together with the Library's multi-select variant of it described in Section 7.2: the Output Directory selector, the Apply to All checkbox, and the progress dialog with cancel. That implementation landed on 09-08-26 (General UI Phase 2); the change log records how Apply to All behaves when unchecked.

Export Formats

Files in the Library can be exported to the following formats, consistent with the Export Dialog defined in the General UI PRD (Section 11.2):

  • PNG: Flattened raster export with configurable DPI, transparency, and color depth.
  • JPEG: Flattened raster export with configurable quality and DPI.
  • PDF: Document export with configurable DPI, page size, and orientation.
  • SVG: Vector export with optional embedded raster images.
  • .smk: Native SnapMock project file. Copies the .smk file to the chosen location, preserving full editability.

Multi-Select Export

When multiple files are selected in the Library panel:

  • Right-click > Export... opens the Export dialog. The dialog includes an additional "Output Directory" selector (in place of the single-file output path) and an "Apply to All" checkbox that applies the same export settings to all selected files.
  • Right-click > Export Quick (PNG) exports all selected files to PNG using the last-used export settings. The user is prompted for an output directory. Files are named using their library display names with the appropriate extension.
  • A progress dialog shows the export progress with a cancel button.
  • If any file fails to export (e.g., permission error), the error is logged and export continues with remaining files. A summary is shown at completion.

Integration with Export Quick

The existing Export Quick (PNG) action in the Main Toolbar and File Menu (Ctrl+Shift+E) continues to work as defined in the General UI PRD. When a library file is the active tab, Export Quick exports using the last-used settings. If invoked from the Library panel context menu on a selection, it performs multi-select export as described above.

Command Definitions

The Library feature introduces the following undoable commands. All commands extend the base Command interface defined in the Technical Architecture PRD.

RenameLibraryFileCommand

Renames a file in the library.

PropertyTypeDescription
file_pathPathPath to the .smk file.
old_namestringThe previous display name.
new_namestringThe new display name.

Execute: Rename the file on disk and update display_name in manifest.json. Update the Library panel and any open tab title.

Undo: Restore the previous name on disk and in manifest.json.

DeleteLibraryFileCommand

Deletes files or folders from the library through the session trash (Section 3.8).

PropertyTypeDescription
pathslist[Path]Paths of the .smk files and folders being deleted; after an undo, where they were restored to.
trash_pathslist[Path]Where each entry sits in the session trash folder while the delete stands (for undo).

Execute: Open tabs for the files are closed by the panel before the command is pushed. Move each entry into the session trash folder under a unique name, record the pairs, refresh the Library panel.

Undo: Move each entry back to its original path, or to the next free name if that path is now taken. Closed tabs are not reopened.

Discard: When the command leaves the undo stack for good, send whatever is still in the session trash to the system trash. The command stack calls this for the oldest command dropped by its limit, for redo history truncated by a new command, and for every command when the stack is cleared. Entries already restored by an undo are untouched.

MoveLibraryFileCommand

Moves file(s) to a different folder within the library.

PropertyTypeDescription
file_pathslist[Path]Original paths of the files being moved.
destination_folderPathThe target folder.
original_folderslist[Path]The source folders for each file (for undo).

Execute: Move files on disk, update any open tab file references, refresh the Library panel.

Undo: Move files back to their original folders.

CreateFolderCommand

Creates a new subfolder in the library.

PropertyTypeDescription
folder_pathPathThe path of the new folder.

Execute: Create the directory on disk, refresh the Library panel.

Undo: Remove the directory (only if empty; if files have been added, undo is blocked with an informative message).

Serialization

The Library feature relies on the existing .smk serialization format defined in the Technical Architecture PRD. The only addition is the optional library_metadata object in manifest.json:

manifest.json Extension

The following field is added to the manifest.json schema:

Field PathTypeSerialization
library_metadataobject | null{"display_name": string, "captured_at": ISO 8601 string, "source": "capture" | "import" | "new"}
library_metadata.display_namestring"display_name": "Capture_2026-03-01_14-23-45"
library_metadata.captured_atstring"captured_at": "2026-03-01T14:23:45Z"
library_metadata.sourcestring"source": "capture"

The library_metadata field is optional. Files that were not created via the Library (e.g., opened from File > Open) do not have this field. The Library panel gracefully handles files without library_metadata by deriving display_name from the filename and leaving captured_at as null.

Session Persistence

The following Library-related state is saved and restored across sessions via QSettings:

  • Library panel dock position, size, and visibility state.
  • Active library directory path.
  • Current view mode (Grid or Preview List).
  • Thumbnail/preview size slider position.
  • Sort order selection.
  • List of open tabs (file paths) and the active tab index, to restore the workspace on next launch.
  • Per-tab view state (zoom level, scroll position) for open library files.

Acceptance Criteria

Library Panel

  • The Library panel can be docked to any edge of the main window, floated as an independent window, and moved to a separate monitor.
  • Panel position, size, and visibility are saved and restored across sessions.
  • Grid View displays thumbnail cards with file name and modified date. Thumbnails render correctly at all slider sizes from 80px to 256px.
  • Preview List View displays rows with thumbnail, file name, file size, date modified, and date captured. Column headers are clickable for sorting.
  • View mode toggle and size slider work correctly and persist across sessions.
  • The search bar filters files in real-time as the user types, case-insensitive, and the file count updates to show filtered results.
  • The library size indicator displays the correct total size and updates when files are added or removed.

File Management

  • Rename: F2 activates inline rename. Enter confirms, Escape cancels. The .smk file on disk and manifest.json are updated. Any open tab title updates immediately.
  • Delete: Delete key or context menu removes files with confirmation. Open tabs for deleted files are closed. Ctrl+Z in the panel restores the files to the library. A file reaches the system trash once its delete can no longer be undone, and never before.
  • Copy/Paste: Ctrl+C copies selected .smk files. Ctrl+V pastes into current folder with conflict resolution.
  • New Folder: Creates a new folder with immediate inline rename. Folder is visible in both grid and list views.
  • Folder navigation: Double-clicking a folder navigates into it. Breadcrumb path allows navigating back. Back button returns to parent folder.

Multi-Select

  • Ctrl+click toggles individual selection. Shift+click selects a range. Ctrl+A selects all files in the current folder.
  • Multi-select batch delete, move, export, and copy work correctly.
  • The context menu adapts appropriately for multi-select (e.g., shows "Delete N files" instead of "Delete").

Drag-and-Drop

  • Dragging PNG/JPEG/BMP/TIFF/GIF/WebP files into the Library panel creates new .smk files with correct auto-naming and source metadata.
  • Dragging .smk files into the Library copies them to the current folder.
  • Dragging files out of the Library to the OS desktop exports flattened PNGs.
  • Dragging files onto folders within the Library moves them.
  • Copy to Clipboard (Ctrl+Shift+C) places a flattened PNG on the system clipboard.

Tabbed Editing

  • Double-clicking a library file opens it in a new tab. Double-clicking an already-open file switches to its tab.
  • Tab bar appears when 2+ files are open and hides for 0-1 files.
  • Ctrl+Tab and Ctrl+Shift+Tab cycle through tabs. Ctrl+W closes the active tab.
  • Switching tabs correctly swaps the canvas, Layer Panel, Property Panel, Tool Options Bar, and undo stack.
  • Each tab maintains its own independent undo/redo history.
  • Library file tabs never show unsaved indicators and never prompt on close.
  • Non-library file tabs show the asterisk (*) dirty indicator and prompt on close if unsaved.

Continuous Write-Back

  • A new capture instantly creates a .smk file in the library directory.
  • Every annotation action (add item, move, resize, property change, delete) writes the updated JSON to the .smk file.
  • The .smk file on disk is always consistent with the current canvas state (verified by closing and reopening the file).
  • Raster data is written only on capture and raster-level operations (crop, resize, flatten).
  • The Library panel thumbnail updates after annotation changes.

Library Menu

  • All Library menu items are present and functional.
  • Open Library switches to a new directory and the panel updates immediately.
  • Move Library moves all files with a progress dialog and updates the stored path.
  • Reveal in File Manager opens the correct OS file manager at the library path.
  • New Canvas creates a blank library file in the folder the panel is showing and opens it in a tab.

Export

  • Single-file export from the context menu opens the Export dialog and produces correct output in PNG, JPEG, PDF, SVG, and .smk formats (General UI implementation).
  • Multi-select export prompts for an output directory and exports all selected files with correct naming.
  • Export Quick (PNG) from the context menu exports using last-used settings without opening the dialog.
  • Export errors are handled gracefully with per-file error reporting and continued processing of remaining files.

Preferences

  • The Library category appears in Preferences with all settings from Section 8.1.
  • Changing the library directory switches the active library.
  • All preference changes take effect immediately.
  • Preferences persist across application sessions.
