09-11-26 23:49 4.2, 4.4, 8.3 Built Eyedropper and Blur performance Phase 2 (09-12-26; notes in docs/Eyedropper-Blur-Performance-Implementation.md, Section 5; decision 2, option A). What is sampled. RenderEngine.render_sample(rect) builds the composite 4.2 describes over the sampled area, in scene coordinates at canvas scale: the canvas colour where the canvas covers the area, then every visible annotation item in stacking order, each painted with its own scene transform and effective opacity. Only SnapGraphicsItem instances are painted, so the grid, the guides, the crosshairs, the marching ants of a raster selection, the crop overlay's dimming and handles, and every future tool overlay are left out by construction, and so is the preview loupe, which is a widget. The render is clipped to the canvas, so a sample beyond the canvas edge is transparent whatever hangs over the pasteboard there (4.3, 8.3). This replaces a 1 by 1 QGraphicsScene.render, which painted no canvas colour at all: a click on empty canvas over a white canvas had reported transparent black. The sample area. sample_size (4.4) is 1, 3, 5, or 11, the side of the square in canvas pixels, centred on the pixel under the cursor; an unrecognised value falls back to 1. The colour is 4.2's arithmetic mean of the red, green, and blue channels of every pixel in the area, with a transparent pixel left out of the mean, since it has no colour to contribute; the result's alpha is the mean over every pixel in the area, so an area half beyond the canvas comes back half transparent and an area with nothing in it comes back fully transparent, which is what "transparent" means in 4.3 and in the 8.3 row. The press, the drag, and the release. A press previews the colour under the cursor and applies nothing; a drag keeps previewing it as the cursor moves, which the Tool Options Bar's colour display follows through a new preview callback; and the release applies the colour under the cursor at that moment, which is what a plain click does too. A focus loss or Escape drops the drag and applies nothing. pick_serial counts applied samples only, so a preview never looks like a pick to the momentary Alt mode or to the colour picker. The bar's colour display reads "transparent" for a transparent sample rather than showing black.

The Blur / Pixelate tool creates regions that obscure content underneath them. This is the essential privacy tool for screenshot annotation: hiding personal information, email addresses, account numbers, faces, and other sensitive content before sharing screenshots. The blur region is non-destructive — it sits on top of the canvas content as a separate item that can be moved, resized, or deleted at any time, and the original content underneath is preserved.

Creation Workflow

Click-and-Drag to Draw Region:

  1. With the Blur tool active, click and drag on the canvas to define the blur region.
  2. The region shape depends on the region_shape setting (see Section 2.4). The default is Rectangle.
  3. During drag, a preview of the blur effect is rendered in real-time within the drawn region. This shows the user exactly how the content will look when obscured.
  4. Shift constrains to a square (for rectangle shape) or circle (for ellipse shape).
  5. Alt draws from center.
  6. On mouse release, the BlurRegionItem is created and added to the scene.

Brush-Style Blur (Freeform region):

  • When region_shape is set to "Freeform", the user paints the blur region with a brush, similar to the Freehand tool.
  • Click and drag to paint the blur area. The brush radius is set by brush_size in the Tool Options Bar.
  • The painted region is stored as an alpha mask (bitmap). Pixels within the painted area are blurred; pixels outside are unaffected.
  • Multiple strokes accumulate into the same region (additive painting). The user can release the mouse and continue painting to add to the region.
  • Pressing Enter or switching tools finalizes the freeform region.
  • This mode is useful for blurring irregular areas (e.g., a person's face that does not fit a neat rectangle).

Minimum Size:

Regions with bounding box area less than 16 square pixels are discarded (accidental click).

Rendering Pipeline

Gaussian Blur Rendering:

  1. Capture the content beneath the blur region as a QImage. This is done by rendering all items below the BlurRegionItem in z-order into a temporary QImage at the region's bounding rectangle.
  2. Apply a Gaussian blur filter to the captured image using the configured blur_radius. Implementation: use QGraphicsBlurEffect or a custom convolution kernel for precise control.
  3. Clip the blurred image to the region shape (rectangle, ellipse, or alpha_mask for freeform).
  4. Apply feathering by multiplying the region's alpha channel with a feather gradient at the edges.
  5. Apply opacity by blending the blurred result with the original captured content at the configured opacity.
  6. Draw the resulting image at the region's position.
  7. If border_width > 0, draw the region outline on top.

Pixelate Rendering:

  1. Capture the content beneath the region (same as Gaussian).
  2. Divide the captured image into a grid of pixel_size x pixel_size tiles.
  3. For each tile, compute the average color of all pixels in the tile.
  4. Fill the entire tile with that average color, producing the mosaic effect.
  5. Clip to region shape, apply feathering and opacity, draw result.

Solid Fill Rendering:

  1. Draw a filled shape (rectangle, ellipse, or freeform mask) in fill_color.
  2. Clip to region shape.
  3. Apply feathering (solid color fades to transparent at the edges).
  4. Apply opacity.
  5. Draw border if configured.

Invert Mask Rendering:

  • When invert_mask is True, the rendering is inverted: the blur/pixelate/fill is applied to everything OUTSIDE the region, while the region interior shows the original content clearly.
  • This creates a spotlight or focus effect: the area of interest is sharp, everything around it is obscured.
  • Implementation: capture the full canvas area, apply the blur to the entire capture, then composite the original (unblurred) content back into the region shape.

Caching:

  • The rendered blur result is cached as a QPixmap on the BlurRegionItem. The cache is invalidated and re-rendered when: the blur properties change (mode, radius, pixel_size), the region is moved or resized, the content beneath the region changes (items are added, moved, or edited on lower layers), or the zoom level changes significantly (> 2x change in either direction).
  • Cache invalidation on underlying content changes is detected by listening to the scene's itemChanged signals for items on layers below the blur region's layer.
  • At 60 FPS zooming, the cache may briefly show a stale blur. This is acceptable; the cache is refreshed when the zoom interaction ends.

Flip transforms: BlurRegionItem inherits flip_horizontal and flip_vertical from the SnapGraphicsItem base class (Technical Architecture PRD Section 3.1.4). When either property is True, the blur region is mirrored around its bounding box center via QPainter scale(-1, 1) or scale(1, -1). Flip is applied after rotation in the rendering transform order.

Post-Creation Editing

Select Tool:

  • Click to select. TransformHandles appear around the region bounding box.
  • Drag to move the region (the blur updates to show the content beneath the new position).
  • Resize via handles resizes the region. Blur re-renders for the new area.
  • For freeform regions, resize scales the alpha_mask proportionally.

Editing Freeform Regions:

  • Double-clicking a freeform BlurRegionItem enters brush editing mode.
  • The user can paint additional blur area (additive) or hold Alt and paint to erase blur area (subtractive).
  • The brush cursor shows the current brush_size as a circle outline.
  • Enter or Escape exits brush editing mode.
  • Editing pushes a ModifyPropertyCommand storing the old and new alpha_mask.

Property Panel:

All properties from Section 2.5 are editable in the Property Panel. Changing blur_mode or blur_radius provides a live preview on the canvas.

Hit Testing

  • For rectangle and ellipse regions: shape() returns the region shape path.
  • For freeform regions: shape() returns the bounding rectangle of the alpha_mask (precise mask-level hit testing would be expensive and is not needed for selection).
  • Blur regions always have a visible effect on the canvas, so they are inherently clickable/discoverable.

Performance

  • Gaussian blur is computationally expensive. The blur is rendered once and cached. Cache invalidation triggers a re-render in a background thread if the region is large (> 500x500 pixels).
  • Real-time preview during drawing: use a lower-resolution blur (render at 50% resolution, scale up) for the preview, then render at full resolution on mouse release.
  • Pixelate is cheaper than Gaussian blur (simple averaging, no convolution). Real-time preview is feasible at full resolution.
  • Solid fill is trivial and always renders at full speed.
  • Target: blur re-render for a 1000x1000 pixel region completes within 100ms. For regions larger than 2000x2000 pixels, a progress indicator is shown.
  • Multiple overlapping blur regions: each region captures and blurs independently. The upper blur region sees the already-blurred content from the lower region. This naturally produces correct stacking behavior.

The Highlighter tool draws semi-transparent colored strokes over the canvas, simulating a physical highlighter marker pen. It is used to draw attention to specific text, UI elements, or areas of a screenshot by overlaying them with a translucent color wash. The highlighter differs from the Freehand tool in its blend mode (multiply), default opacity, and auto-straightening behavior.

Drawing Behavior

Mouse Press:

  • Verify the active layer is visible and unlocked.
  • Record the press position as the first point.
  • Begin capturing mouse move events.
  • Change cursor to the angled marker tip icon.

Mouse Move (Drawing):

  • Append the current mouse position to the raw stroke path.
  • Render the stroke in real-time with the current highlight color and blend mode.
  • The stroke has a flat, wide shape: it is rendered as a broad band (stroke_width range 10-80px, default 24px) with flat ends (stroke_cap = Flat by default).
  • The stroke is rendered with the configured blend_mode (default: Multiply), which interacts naturally with the content underneath: dark content shows through the highlight, light content takes on the highlight color. This matches the behavior of a real highlighter on paper.
  • Path smoothing is applied in real-time using a simple moving-average filter on the last 5 points, producing a naturally smooth stroke without the post-processing delay of the Freehand tool.

Mouse Release:

  • Apply auto-straightening if enabled (see Section 3.3).
  • Apply path simplification (Ramer-Douglas-Peucker with a tolerance of 2px) to reduce point count.
  • If the resulting stroke is shorter than 4 pixels, discard (accidental click).
  • Finalize the HighlightItem. Add to scene and active layer. Push AddItemCommand.
  • Return to Idle.

Straightening & Snap-to-Line

Auto-Straighten:

  • When auto_straighten is enabled (default: True), the tool analyzes the completed stroke path to determine if the user intended a straight line.
  • Straight-line detection: compute the ratio of the path's arc length to the Euclidean distance between start and end points. If the ratio is less than the straighten_threshold (default: 1.15, meaning the path is within 15% of a straight line), replace the entire path with a single straight line from start to end.
  • This allows users to quickly highlight a line of text by drawing an approximately straight stroke — the tool cleans it up into a perfectly straight highlight.
  • If the ratio exceeds the threshold, the path is kept as-is (freeform).
  • Auto-straighten applies on mouse release, before the AddItemCommand is pushed. The user sees the straightened result immediately.

Manual Straight Mode (Shift):

  • Holding Shift while drawing forces a perfectly straight highlight from the press point to the current cursor position, regardless of mouse movement.
  • The angle is NOT constrained (unlike Shift in the Line tool). The line follows the exact angle from start to cursor. This is intentional: for highlighting text, the user typically wants a horizontal-ish stroke that follows the text baseline exactly.
  • If the user wants angle-constrained straight highlights, they can hold Shift+Alt, which constrains to 15-degree increments (horizontal, vertical, diagonal).

Snap to Horizontal/Vertical:

  • When snap_to_axis is enabled and the stroke angle is within 5 degrees of horizontal or vertical, the stroke is snapped to a perfectly horizontal or vertical line.
  • This is a secondary correction applied after auto-straighten. It only triggers on strokes that have already been straightened to a line.
  • This ensures that highlights drawn roughly along text lines become perfectly horizontal.

Post-Creation Editing

Select Tool:

  • Click to select. TransformHandles appear around the stroke bounding box.
  • Drag to move.
  • Resize scales the entire stroke (all path points scale relative to bounding box center). Stroke width also scales proportionally.
  • Rotate rotates the stroke around its bounding box center.

Point Editing Mode (Double-Click):

  • Double-clicking a selected HighlightItem enters point-editing mode.
  • For straightened strokes (only 2 points), the two endpoints are shown as draggable handles. The user can adjust the start and end of the highlight.
  • For freeform strokes, the simplified path points are shown as handles, similar to the Freehand tool's point-editing mode.
  • Escape exits point-editing mode.

Property Panel:

All properties including highlight_color, stroke_width, stroke_style, blend_mode, and cap_style are editable. Changes apply immediately with live preview. Changing auto_straighten or snap_to_axis has no retroactive effect (they only apply during drawing).

Rendering

Blend Mode Implementation:

  • The blend mode is implemented using QPainter's CompositionMode. The key modes and their visual effect:
  • Multiply (CompositionMode_Multiply): darkens the content beneath the highlight. White content becomes the highlight color. Dark content stays dark. This is the most natural highlighter simulation.
  • Overlay (CompositionMode_Overlay): increases contrast. Bright areas get brighter, dark areas get darker, with the highlight color tinting everything.
  • Soft Light (CompositionMode_SoftLight): a gentler version of Overlay. Subtly tints the content with the highlight color without harsh contrast changes.
  • Normal (CompositionMode_SourceOver): standard alpha blending. The highlight simply sits on top with its alpha transparency. No color interaction with the content beneath.

Rendering Steps:

  1. Construct a QPainterPath from the stroke path_points.
  2. Create a QPen with highlight_color, stroke_width, stroke_style, stroke_cap, and Round join.
  3. Save the QPainter state.
  4. Set QPainter.setCompositionMode() to the configured blend_mode.
  5. Draw the path with the configured pen.
  6. Restore the QPainter state (reset composition mode to SourceOver).
  7. If shadow_enabled: draw the shadow with normal composition mode (shadows should not use blend modes).

Opacity Handling:

The highlight_color's alpha channel is the primary opacity control. Item-level opacity (inherited from SnapGraphicsItem) is multiplicative. For example: highlight_color with alpha 204 (80%) at item opacity 0.5 produces an effective alpha of 102 (40%).

Flip transforms: HighlightItem inherits flip_horizontal and flip_vertical from the SnapGraphicsItem base class (Technical Architecture PRD Section 3.1.4). When either property is True, the highlight stroke is mirrored around its bounding box center via QPainter scale(-1, 1) or scale(1, -1). Flip is applied after rotation in the rendering transform order.

Hit Testing

  • The shape() returns a QPainterPathStroker result of the stroke path with the stroke_width + 4px padding.
  • For wide strokes (> 20px), clicking anywhere within the stroke band selects it.
  • The blend mode does not affect hit testing (hit testing uses geometry, not rendering).

The Eyedropper tool samples colors from the canvas and applies them to other tools or items. Unlike all other tools, the Eyedropper does not create scene items. It is a utility tool that reads pixel colors and sets color properties on other tools and items. It is also available as a temporary mode (Alt key) from within other tools.

Sampling Behavior

Single-Point Sampling (Click):

  1. With the Eyedropper tool active, click on the canvas.
  2. Sample the pixel color at the click position. The sampled color is a composite of all visible content at that point (all visible layers composited together, including the canvas background).
  3. The sampled color is stored as the "last sampled color" and applied to the target (see Section 4.6).
  4. The tool remains active after sampling. The user can click again to sample a different color.

Click-and-Drag Sampling (Live Preview):

  • Click and hold, then drag across the canvas. As the cursor moves, the color under the cursor is continuously sampled and displayed in the preview loupe (see Section 4.3).
  • The Tool Options Bar color display updates in real-time as the cursor moves.
  • On mouse release, the color under the cursor at the release position is applied as the sampled color.
  • This allows the user to visually find the exact pixel they want to sample.

Sample Area:

  • By default, the eyedropper samples a single pixel. However, the sample_size property can be set to sample an area and average the colors:
  • 1x1 (Point): samples the exact pixel under the cursor. Most precise.
  • 3x3: averages a 3x3 pixel area centered on the cursor. Reduces noise in dithered or anti-aliased areas.
  • 5x5: averages a 5x5 area. Good for sampling the "general" color of a region.
  • 11x11: averages an 11x11 area. Captures the dominant color of a larger area.
  • The averaged color is a simple arithmetic mean of the RGB values of all pixels in the area.

Preview Loupe

While the Eyedropper tool is active (or during Alt-key temporary activation), a magnified loupe follows the cursor to help the user see exactly which pixel they are sampling.

Loupe Appearance:

  • A circular magnification window, 120px diameter, positioned 20px above and to the right of the cursor (repositioned if it would go off-screen).
  • Magnification level: 8x (each pixel is rendered as an 8x8 block in the loupe).
  • A thin crosshair in the center of the loupe indicates the exact sample point.
  • The sampled pixel (or sample_size area) is highlighted with a small colored square outline in the loupe.
  • Below the loupe circle, a small rectangular color swatch (40x24 px) shows the sampled color, with the hex value displayed beneath it in a small font (e.g., "#4A90D9").
  • The loupe has a 2px border in the accent color and a subtle drop shadow for visibility against any background.
  • If the cursor is over transparent canvas (no content), the loupe shows the checkerboard transparency pattern and the color swatch shows "transparent".

Loupe Rendering Performance:

  • The loupe captures a small region of the canvas (approximately 15x15 pixels at 8x magnification = the area that fits in the 120px loupe) and scales it up using nearest-neighbor interpolation (no smoothing, to show exact pixel boundaries).
  • This capture and render must occur every frame (60 FPS) during drag. For efficiency, the capture area is small and the render is a simple scaled blit.
  • The loupe is rendered as a temporary overlay on the viewport (not a scene item). It is drawn in QGraphicsView.drawForeground() or as a QWidget overlay.

Color Output & Integration

Applying the Sampled Color:

When a color is sampled, it is applied based on the apply_target setting and the context:

  • If the user was using a shape/annotation tool before switching to the Eyedropper, the sampled color is set as the configured target property (stroke_color, fill_color, etc.) on that tool. When the user switches back to the previous tool, the new color is ready to use.
  • If items are currently selected (the user had items selected before activating the Eyedropper), the sampled color is applied directly to the selected items' target property. This pushes a ModifyPropertyCommand and is undoable.
  • If no items are selected and no previous tool context exists, the sampled color is stored as the application's active stroke_color (default target).

Integration with Color Picker:

  • The sampled color is also pushed to the Color Picker's "Recent Colors" list.
  • If the Color Picker popover is open (e.g., the user opened it from a tool options bar swatch), sampling a color with the Eyedropper fills the Color Picker with the sampled value and selects it.

Alt-Key Shortcut Mode

The Eyedropper is available as a temporary mode from any tool by holding the Alt key (as defined in the General UI PRD keyboard conventions).

Workflow:

  1. While using any tool (e.g., Arrow, Rectangle, Text), the user presses and holds Alt.
  2. The cursor changes to the Eyedropper icon. The loupe appears.
  3. The user clicks (or holds and drags) to sample a color.
  4. On mouse release, the sampled color is applied to the currently active tool's primary color property (stroke_color for shape tools, highlight_color for the Highlighter, text_color for the Text tool, badge_color for Numbered Step).
  5. The Alt key is released. The cursor returns to the previous tool's cursor. The tool continues as before, now using the new color.
  6. The user never had to leave their current tool. This is the fastest way to pick a color while annotating.

Alt-Key Behavior Details:

  • Alt+click during an in-progress drawing operation (e.g., the user is mid-drag drawing a rectangle): the eyedropper activates temporarily, samples the color, and the drawing operation continues with the new color applied when the user resumes.
  • Alt does NOT activate the eyedropper if the user is in inline text editing mode (Alt is used for other purposes in text editing). In text editing mode, the eyedropper is accessed via the Tool Palette or keyboard shortcut (I).
  • The loupe preview appears instantly when Alt is pressed, even before clicking, allowing the user to see what color is under the cursor.
  • If the user presses Alt but does not click (just previews), releasing Alt returns to the previous tool with no changes.

Serialization

BlurRegionItem Serialization

  • All properties are serialized to JSON in items.json as standard key-value pairs (see Section 5.1).
  • Freeform alpha masks: for small masks (< 100KB as PNG), the base64 PNG data is stored inline in the alpha_mask_data field. For larger masks, the PNG is stored as a separate file in the .smk archive's raster/ directory (e.g., raster/blur_mask_a1b2c3d4.png), and alpha_mask_data contains the filename reference prefixed with "file:" (e.g., "file:raster/blur_mask_a1b2c3d4.png").
  • On deserialization: if alpha_mask_data starts with "file:", load the PNG from the archive. Otherwise, decode the base64 data directly.
  • The blur cache is NOT serialized. It is regenerated on project load.

HighlightItem Serialization

  • All properties are serialized to JSON with the path_points as an array of {x, y} objects.
  • The blend_mode is stored as a string identifier ("multiply", "overlay", etc.) that maps to QPainter::CompositionMode on deserialization.
  • The highlight_color is stored with alpha (e.g., "#FFFF00CC" for yellow at 80% opacity). The 8-character hex format includes the alpha channel.

Eyedropper

The Eyedropper has no serialization requirements. Its session state (last_sampled_color, color_history) is transient and not saved with the project. The sampled color history could optionally be saved in application preferences (QSettings) for persistence across sessions.

Acceptance Criteria

Blur / Pixelate Tool

  1. Click-and-drag creates a blur region at the drawn position and size with real-time blur preview during drawing.
  2. All three blur modes render correctly: Gaussian blur produces a smooth, unreadable result at radius 10+. Pixelate produces a clean mosaic grid. Solid fill completely hides content.
  3. Gaussian blur radius is visually proportional: radius 1 is barely noticeable, radius 50 makes content completely unrecognizable.
  4. Pixelate pixel_size is visually proportional: size 2 is nearly invisible, size 50+ produces very large mosaic tiles.
  5. Rectangle and Ellipse region shapes work correctly with Shift (constrain) and Alt (from center) modifiers.
  6. Rounded rectangle (corner_radius > 0) produces smooth rounded corners on the blur region.
  7. Freeform brush mode allows painting irregular blur regions. Multiple paint strokes accumulate additively.
  8. Freeform editing mode (double-click) allows adding (paint) and erasing (Alt+paint) blur area.
  9. Feathering produces a smooth gradual transition at the region edges.
  10. Invert mask mode blurs everything OUTSIDE the region, creating a spotlight effect.
  11. Moving or resizing a blur region updates the blur to reflect the new underlying content.
  12. Non-destructive: deleting a blur region fully restores the original content beneath.
  13. Opacity slider allows partial blur effects (50% opacity shows a blend of blurred and original).
  14. Performance: Gaussian blur of a 1000x1000 region renders within 100ms. Pixelate renders within 50ms.
  15. Blur regions on locked/hidden layers cannot be created. Status bar warning is shown.

Highlighter Tool

  1. Click-and-drag draws a semi-transparent colored stroke with the configured width.
  2. Multiply blend mode produces a natural highlighter effect: white backgrounds take the highlight color, dark text shows through.
  3. All four blend modes (Multiply, Overlay, Soft Light, Normal) render correctly and produce visually distinct results.
  4. Auto-straighten correctly detects approximately-straight strokes and replaces them with perfectly straight lines. Curved strokes are not incorrectly straightened.
  5. Manual straight mode (Shift held) produces a perfectly straight highlight from press to release.
  6. Shift+Alt constrains the straight highlight to 15-degree angle increments.
  7. Snap-to-axis correctly snaps near-horizontal strokes to perfect horizontal and near-vertical to perfect vertical.
  8. The default stroke width (24px) and flat cap style produce a clean, marker-like appearance.
  9. Preset highlight colors (Yellow, Green, Cyan, Pink, Orange, Purple) are quickly accessible in the Tool Options Bar.
  10. Point-editing mode allows adjusting endpoints of straightened highlights.
  11. Strokes shorter than 4 pixels are discarded (accidental clicks).
  12. Highlight strokes render correctly at all zoom levels from 10% to 3200%.

Eyedropper Tool

  1. Clicking on the canvas samples the correct composite pixel color from all visible layers.
  2. Click-and-drag shows real-time color sampling with the preview loupe and continuously updating color display.
  3. The preview loupe renders correctly: 8x magnification, crosshair at center, pixel grid visible, sampled color swatch and hex value below.
  4. The loupe repositions to stay on-screen when the cursor is near screen edges.
  5. All four sample sizes (1x1, 3x3, 5x5, 11x11) sample correctly. Averaged colors are visually plausible (not noisy or distorted).
  6. Sampled color is correctly applied to the previous tool's stroke_color (or configured apply_target).
  7. Sampled color is correctly applied to selected items when items are selected before activating the Eyedropper. The change is undoable.
  8. Copy to Clipboard correctly copies the hex value to the system clipboard.
  9. Color Format dropdown correctly displays the color in Hex, RGB, and HSL formats.
  10. Color History shows the last 8 sampled colors. Clicking a history swatch re-applies that color.
  11. Alt-key shortcut mode works from all tools: Alt activates the loupe, click samples, release returns to the previous tool with the new color applied.
  12. Alt-key mode does NOT activate during inline text editing (Alt is reserved for other purposes in text edit mode).
  13. Sampling transparent areas correctly reports "transparent" and shows the checkerboard pattern in the loupe.
  14. Loupe rendering maintains 60 FPS during drag sampling.

Shared Behavior

  1. Blur and Highlighter tools respect active layer: cannot draw on locked/hidden layers.
  2. All item creation produces AddItemCommand and is fully undoable.
  3. All property changes produce ModifyPropertyCommand and are undoable.
  4. All items serialize and deserialize correctly with full property fidelity.
  5. Blur and Highlight items support copy, cut, paste, and duplicate operations.
  6. All tools display appropriate status bar hints in all states.
  7. Tool Options Bar updates correctly when switching between tools and when selecting existing items of each type.
